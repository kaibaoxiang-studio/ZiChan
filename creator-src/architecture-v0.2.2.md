# 角色资产插件 0.2.2 增量设计

## 范围

保持小版本，沿用已有项目状态、四阶段审批、GPT Image 2.5 文字提示词和头像默认 3:4。旧 V1/V2/V2.1 已批准卡继续可读；新提交的重点人形卡使用 V2.2。新增一个特征聚焦专项；形体专项扩充三维体块。能力数 17→18，知识快照 22→27。

## v0.2.1 的根因

旧卡的 `specialist_coverage` 仅验证 `proposal_ref` 非空及 `applied_fields` 名称有效，无法证明专项被真正调用、提案属于该角色、被选方案存在或文件仍未改动。总控路由只写在自然语言规则里，没有逐人交接物；知识快照虽存在，激活证据不完整。

## v0.2.2 的调度与交接

1. 群像比较后，逐人先写 `CharacterSpecialistRouteV1`，覆盖 11 专项，每项 `invoke|skip`、具体触发点和理由。由主控决定是否调用，避免固定工作流强迫全部专项运行。
2. invoke 的专项实际返回 `CharacterSpecialistProposalV1.1`，总控将原样 JSON 存到项目 `drafts/specialists/`。操作者在合并审阅轮中选择方案；未选择时卡保留 unresolved，不可批准。
3. `CharacterDesignCardV2.2` 的 used 项记录提案路径、SHA、所选 option ID 和 `design_elements` 到 `visual_details` 字段的映射。提交、批准及下游读取时脚本复核路径边界、哈希、角色、专项、方案与字段；不宣称能机器判断审美或语义一致。
4. `feature_focus` 记录角色一句话识别核心、主锚点/安静区、是否采用自然不对称和视角测试状态。`body_form` 记录相对四肢比例、颅胸盆体块、正侧背形态、站姿和剧本动作。未实际见图时相关视觉测试填 `not_tested`。
5. 提示词只抽取当前画幅可见的已批锚点；回图审查区分设计分散、提示词遗漏与模型漂移。真正修改外观仍走原审批。

## 知识边界

两份新 ZIP 原文只进忽略的私有源库；提交归档与成员哈希及独立重写的 5 份规则。2–3 个主锚点是可解释的默认建议，非硬阈值；无需自动制造痣疤或瑕疵。课程关于平均脸记忆、舞蹈招生数值、形状与人格的因果说法未独立核实，不进入强制规则。人体相对比例应服务世界观、行动和多视角一致性。

## 验收

构建与 Harness validate/doctor；真实小样检查 V2.2 提交的有效交接以及虚假路径、改动哈希、错角色、错专项、未选方案、路由不匹配均被拒绝；旧版卡可读；知识快照哈希与发布包一致；README、版本、安装包与远端提交一致。视觉美感仍需成图后人工审阅。
