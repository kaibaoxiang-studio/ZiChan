# v0.2.4.1 需求路由、阶段合同与整合

## 1. 接收需求

先把请求写成 `CharacterAssetRequestV1`：`project_id`、角色 ID 范围、资产表状态 ID 范围、`mode: single|batch`、目标阶段、已有批准物的 SHA、剧本事实引用、用户明确选择、画幅或模卡例外、未决项。单张只选一个阶段与状态；批量只是把多个独立任务放入同一队列，**每张图仍单独提示、回图、审查和批准**。`python scripts/character_project.py plan --project-root ... [--character-id ...] [--variant-id ...] [--stage ...]` 给出当前可做和阻断项；`--character-id` 可重复指定多个角色，无此参数为全员批量规划。计划不自行生成或批准图片。

## 2. 路由与责任

| 时机或缺口 | 主责 | 输入与可检验输出 |
| --- | --- | --- |
| 项目启动或来源变更 | `character-evidence`，再由 `character-design` 主控 | 原文事实、资产表状态、可选场记、冲突表；项目视觉基准和比较组 |
| 世界规则、环境暴露、资源与可达技术会改变外观 | `character-world-appearance-design` | 每个可见影响的接触方式、部位、材料/护理/装备、依据、状态与视角；无证据则 skip |
| 群像撞型或主次不清 | `character-cast-differentiation`、`character-feature-focus` | 比较组、主锚点、安静区及未验证视角 |
| 具体发、脸、身体、皮肤缺口 | 对应专项 | 2–3 个可画提案；身体含可复核比例和体块 |
| 痣疤、面绘、眼唇妆、花妆等面部表面状态 | `character-face-decoration-design` | 稳定/施加/临时分层，位置形态、剧情依据、起止状态及焦点竞争；无需求则 skip |
| 饰品、衣装结构、材质、色块缺口 | 对应头颈或服饰专项 | 部位、固定/连接、前侧背结构、材料及状态；同物件只设一个主责 |
| 已批准设计变为单张图 | `character-image-prompt` | 仅当前阶段可见锚点、参考图职责、提示词包和验收项 |
| 图片回流或局部缺陷 | `character-image-review`，必要时 `character-image-edit` | 实际看图后的分级问题；局部修图后整张重审 |

专项路由先于专家提案，以 `invoke/skip`、触发证据、原因和适用字段记录。新重点人形卡 `CharacterDesignCardV2.4` 覆盖 13 项，used 项必须有经过校验的提案、SHA、被选方案和字段映射。路线不是强制 13 个都执行；无缺口要写 skip 原因。事实优先级：剧本原文和明确用户决定；再是已批准视觉基准与设计卡；最后才是专项建议。冲突上报主控与操作者裁决，专家不能互相覆盖。

## 3. 正式五阶段

| 序 | 阶段 | 资产粒度 | 本阶段固定什么 | 进入下一阶段的门槛 |
| --- | --- | --- | --- | --- |
| 1 | `avatar` 头像 | 每角色一组 2–3 候选，定一张；默认 3:4 | 原创脸、发、稳定标记、身份气质；无角色服装设计 | 图片实际审查通过并由操作者选定 |
| 2 | `expression` 九宫格 | 每角色一张 3×3，中文标签；16 格仅明确用户要求 | 同一身份的剧情表情幅度，不逐格换妆换装 | 九格逐格审查通过并批准 |
| 3 | `full_body` 全身模卡 | 每角色一张；默认 9:16 | 同一身份的身体比例、体块、体态；中性背心短裤赤脚 | 头、手、脚、比例与前两图一致并批准 |
| 4 | `costume_design` 服饰设计 | **每个资产表状态/变体一张**；无状态则 base 一张 | 当前变体服装、鞋履、饰品、前侧背关键结构及有依据的妆面状态 | 与该状态设计卡、基础全身图一致并批准 |
| 5 | `execution` 执行资产图 | 每个状态/变体一张 | 用头像、表情、全身模卡和**同状态已批准服饰图**制作四格执行参考 | 四格及状态连续性审查通过后可打包 |

前三阶段归角色 `base`，服饰与执行归状态 ID。服饰状态必须来自资产表；不能用故事情绪临时多造一个状态。参考示例：头像、九宫格、全身参考图只控制各自版式和中性衣着，不能带入参考图的人脸、妆容或未批准背景。三张示例图分别见 `examples/reference-images.md` 的绝对本地路径说明；正式插件不打包用户私人图片。

## 4. 集成与变更

同一角色的设计卡保存世界影响 `world_influences`、面部表面 `facial_surface`，并分开身份不变量和变体状态。头像、表情、全身只引用 base 卡；服饰与执行引用当前状态卡。世界影响与妆容既要能在卡片中追溯，又要在提示词里只保留当前画幅可见项。`anchor_images` 存每个上游已批准图的 SHA；回图记录提示词 SHA、审查 SHA 和操作者批准。打包输出 `CharacterAssetPackV2` 和可读图片文件名。上游身份变更重审全部下游；某状态服饰变更只重审该状态执行图。旧四阶段项目保留其既有门槛，不自动迁移或重画。

从 Skill Orchestrator 静态方法中吸收：需求规格化、按缺口路由、明确交接边界、证据优先级、合成时裁决冲突、上游变更仅使受影响后代失效；本插件独立实现，不调用或复制其私有控制器。
