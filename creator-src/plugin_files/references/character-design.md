# 项目视觉基准、人物定位与角色设计 v0.2.5

先执行 [角色设计总控](director-understanding.md)：阅读全文并建立可复用理解，联读言行与关系，定位人物、弧线和观众信息，形成设计意图，再执行专项或加载知识。不要从职业、阶层标签直接跳到外貌，也不要等原文写出外观才开始设计。

## 项目基准与全员轻规划

从剧本、资产表与可选场记提取世界规则、时代、空间、社会资源、人物关系和叙事气质。默认给一套推荐视觉基准，重要分歧才给备选。媒介、写实度、色彩、材质和气质分别说明，确认后形成 `ProjectVisualBibleV1`；一个古风或二维标签不代表批准整套视觉设定。

读取资产表全量角色，保留 ID、层级和状态。按 [群像差异化框架](differentiation-framework.md) 建立同框或叙事近邻比较组，完成 `CastPlanV2`；五轴是对照索引，不替代人物理解。共享圈层和制服可以保留共性，再选择有意义的个体差异。检查是否全员同脸、同发型、修长身材或只靠换色区分；不为差异硬造极端特征。

投入粒度结合剧情作用、镜头距离、混淆风险与状态数量，不只看主角标签。重点角色深入关键矛盾和转折；配角聚焦辨识问题；群演使用群体规则与有限个体变量。轻规划无需等全员详设完才开始第一个人物。

## 默认人物决策

呈现跨场证据支持的人物理解、定位和一套推荐设计意图，集中确认会改变结果的方向。直观、反差或隐藏均可；不要求所有性格和过往从外表直接读出。普通细节由主控主动补齐，普通痣雀斑随首稿确认；新增身份、经历或剧情含义的特征显式提出。

默认 `phased`：方向先确认，身份阶段可先看头像；身体和各状态服饰随后深化。首图快看按 [阶段设计与预览转正](phased-design.md) 保存依据，不能把 preview 当作正式下游锚点。用户要求先完整定卡时用 `complete`。不固定强制五轮 Grill Me；关键矛盾或用户要求时深挖，合并相关待选项，不为每个专项另开一轮确认。

理解和意图明确后按 [专项交接](specialist-contract.md) 路由：普通项主控真实执行专项规范，复杂项独立会诊。默认一套推荐，重要分歧才备选。当前阶段快照与 `CharacterDesignCardV2.5` 对十三项专项记录执行方式和可见成果，不能只填名称。最终卡由阶段快照合成；旧卡兼容见 [接口](interfaces.md)。

## 具象检查

1. 脸部写脸长宽、额颧颌连接、眉眼距与眼睑、鼻尖唇线、发际关系；英俊、清秀、聪明不能代替结构。性格与脸型、阶层与美丑不存在固定映射。
2. 发型写前侧后轮廓、分缝/刘海、发量发质、长度颜色和固定；结合本人行动、打理与自我呈现，不复制全员模板。
3. 重点人物保留少量主锚点和安静区；不为记忆点强加伤痕、首饰或夸张人体。近邻共有语言与可见区分同时成立。
4. 身体阶段写明确头身比、肩胯、同端点上段/下段、肘腕膝踝参照、颅胸盆体块和动作；身高体重不构成比例设计。
5. 衣装写领肩袖腰摆、衣层、缝线闭合、连接、材料厚度垂坠、色块、活动余量与维护；细节服务人物。
6. 脸、发型、身体、正式服饰在对应阶段深化；当前图只提可见内容。模卡没有剧情服装不等于删掉服饰设计，正式衣装由每状态服饰图和执行图承接。
7. 回图核对当前批准依据和上一步图片；看不到的侧背、材质、小脸标为未验证。

完整标准见 [设计细节](design-detail-standard.md)，比例与焦点见 [焦点和形体](feature-focus-and-body-form.md)。历史 V1/V2/V2.1/V2.2/V2.4 批准记录保持可读；升级不自动改卡、转正或重画。
