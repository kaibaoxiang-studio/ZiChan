# 最终交付：有设定图资产表

角色资产项目进入最终交付时，除逐角色资产包外，交付一份与上游资产表对应的“有设定图”工作簿。已有 XLSX 资产表时在副本中添加图片列；上游只有 JSON/Markdown 而用户需要工作簿时，先以相同角色 ID、状态 ID、状态名建立可核对的 XLSX。保留上游原件、原有工作表、字段、行序和非图片数据，另存清晰命名的版本。

## 图片与状态定位

- 用资产表的稳定角色 ID 和状态 ID 定位行，不依靠行号或姓名猜测。基础头像、九宫格表情、全身模卡放在该角色首个对应行的独立列；每个状态的服饰执行图放在该状态行。群演和群像按其实际交付阶段映射，不虚构缺失的前三张基础图。
- 每张图片核对角色、状态、阶段、文件 SHA 与当前批准记录。图片尚处于测试或待审时可以另出“测试预览”表，逐行标明未批准，不命名或宣称为最终定稿资产表。已批准的最终表不混入候选图或过期图。
- 图片列标题写清资产类型；状态、来源版本和批准状态可从同一行辨认。图片应完整可辨，单元格尺寸按图片用途设置，避免遮挡文字与相邻行列。

## 单元格内图片硬性规则

- 最终 XLSX 中的设定图必须作为**单元格内图片**插入，图片字节随工作簿保存。单纯覆盖在格子上的浮动图片，即使锚点对齐、设置“随单元格移动和缩放”，也不合格；外部 URL 图片公式也不能代替本地嵌入。
- 选用能写入原生单元格图片的工具或目标表格应用的“嵌入单元格图片”功能。若当前表格 API 只会创建 drawing/anchor 浮动对象，改用支持此功能的导出方式，不能用浮动图假冒完成。
- 交付前逐图对账：图片单元格地址与角色/状态/阶段映射一致、数量齐全；重新打开 XLSX，在目标表格应用中看到图片位于单元格内部，并检查筛选、调整行高列宽时图片仍随所属单元格呈现。对 Excel 原生格式，可检查图片单元格有 rich value 元数据且包内包含图片字节；只有 drawing 锚点不算通过。保留上游非图片数据并抽样检查其他工作表。
- 若交付环境无法生成或核验真正的单元格内图片，明确报告阻碍，把工作簿标为待完成，不把浮动图片版称作最终输出物。

逐角色 CLI `package` 负责角色资产包；有设定图资产表是项目级最终交付物，不能因为角色包已打好就省略。尚无回流图片或当前仅授权文字与提示词时，记录为后续交付，不制作空白“最终有设定图版”。
