# 阶段设计与具象描述标准 v0.2.5

## v0.2.6 服饰颗粒度

每状态正式服饰文字稿须描述前背结构、裁片与闭合、层次、活动余量、材料物理、色块、镜头焦点和妆造状态；“白色婚纱”“得体工作服”只是剧本类别，不是设计。人脸结构按原创脸型、比例、五官主次和稳定肤质锁定；状态妆面不换脸。详见 `costume-designer.md` 与两份新增知识快照。


## 交付目标

先按 [总控方法](director-understanding.md) 完成全文理解、人物定位和设计意图，再把当前阶段细化到另一位设计师能画出同一个人。新 phased 流程使用 `CharacterStageDesignV1`，最终由批准快照合成 `CharacterDesignCardV2.5`；六组不在头像前一次强制填完。既有批准记录继续有效，补改旧卡须明确版本与影响。知识库示例不能当人物事实。

`visual_details` 按身份、身体、服饰阶段分六组记录；当前阶段的每组写可见的**形状、位置/比例、结构关系或物理表现**，再说明与角色行动、世界工艺或近邻角色的关系。没有首饰也要写清哪些位置留空以及造型重心在哪里；不得因表格存在而硬添首饰、伤疤或脏污。非人形态按实际部件改写，允许继续用 V2 合同。

原有 `appearance{}` 和 `costume{}` 作为阅读摘要，从 `visual_details` 提炼；若摘要与详细字段冲突，先修卡再提交。`recognition_axes` 是群像对照索引，不能用来替代详细结构。

| 组 | 必填字段 | 设计卡应能回答 |
| --- | --- | --- |
| `face` | `contour`, `brow_eyes`, `nose_mouth` | 额颧颌如何连接；眉眼距、眼睑、鼻尖、唇线有哪些可画的比例和微不对称？ |
| `hair` | `hairline_part`, `volume_flow`, `length_texture_color` | 前侧后轮廓、分缝和发际线在哪里；发量、发束、末端和颜色如何稳定？ |
| `body` | `frame_proportions`, `weight_posture` | 测量姿态下头高与全高、肩胯、明确端点的上段与下段、肘腕膝踝的参照关系如何；重心、常态站姿与行动余量如何？ |
| `skin` | `tone_variation`, `surface_distribution` | 色调与局部色差在哪里；毛孔、绒毛、细纹或粗糙度的分布与强度如何？ |
| `costume` | `silhouette_layers`, `neckline`, `shoulder_sleeve`, `seams_fastening_mobility`, `material_drape_wear`, `color_placement` | 衣层轮廓、领肩袖腰摆、缝线闭合、材料厚度/垂坠/磨损、主辅色面积和落点如何？ |
| `adornments` | `head_neck`, `body_hands` | 头耳颈与衣身腰手的饰件是否存在；若存在，形制、尺度、固定与道具连续性如何？ |

方向稿对十三项专项规划 `inline|independent|defer|not_needed`，阶段稿以 `specialist_execution` 记录实际执行。主控 inline 须有真实知识路径/SHA、具体采用规则与字段结果；独立会诊须有原样提案、SHA、所选方案和元素映射，详见 [专项合同](specialist-contract.md)。最终 V2.5 卡的 `specialist_coverage` 从这些执行收据合成，不能用标签替代可见成果，也不为十三项固定十三轮。尚未进入的阶段写延期，不伪称无需设计。

## 从概括句到可画设计

例如“奶油白薄衬衫，领口和肩部结构清楚，布料自然垂落”只有颜色、品类和抽象评价。以下是**宋也画画日常造型的示意待审提案**，并非该角色已批准事实：

> 衬衫外轮廓略离身，肩点在自然肩骨外侧约半指；偏窄的软翻领在锁骨上方停住，后领座短而贴颈。前片以窄门襟收住，胸下两侧各一条极浅的收省，保留握笔与抬臂余量。长袖肘位略宽，袖口双层窄翻边可卷到小臂中段；侧缝下摆有短开衩。奶油白细密平纹棉在肩部保持轻微形，腰侧形成几道软折，门襟与袖口可见密针脚；主衣与浅灰蓝裤形成明度差。不添无来源的颜料污迹。若保留无首饰方案，耳颈与手腕明确留空，视觉焦点落在领口、袖口和握笔姿态。

同一示意还应把其他部位写到可画程度，而不是在服装段详细、人物本身仍只写“清秀”：

- **脸与五官待审**：软椭圆轮廓从额角向颧侧轻微放宽，再向下颌缓缓收窄；眉头较平、眉尾略向下，眼睑折线在眼尾变浅；鼻尖偏圆，唇峰柔和，左右嘴角高度有极轻微差别。
- **发型待审**：深棕近黑的偏侧分从左眉上方起，额前有短发束顺势越过发际；两侧贴耳而后脑保留低位圆弧体积，发尾到锁骨下缘，发丝偏细且不做整齐烫卷。
- **体态与皮肤待审**：由主控提出无鞋正立的测量端点和头高对全高、肩峰对骨盆外缘、上段对下段、肘腕与膝踝的具体关系，在身体阶段集中审阅；仅写“肩骨较窄、腿修长”不能交付。站立时肩胛略收、重心落在双脚中间；肤色以暖中性为底，双颊比额头稍有自然血色，鼻翼附近的毛孔只在近景可见，颧侧保留细微肤色差，不做均匀高光。
- **饰品待审**：若此日常状态不佩戴首饰，耳垂、颈口与手腕都留空；辨识点由偏分发流、窄翻领和可卷袖口承担，不靠临时加项链或戒指。

上面具体细节是示意创作推荐，随对应阶段确认；不能直接改写既有宋也批准卡。新身份草案可按 [预览规则](phased-design.md) 冻结后先看首图，正式采用须完成同 SHA 确认与图像审查。尤其该角色其他剧情状态可能有已写明的手链、项链或工作牌；基础日常造型的“无饰品”不能覆盖那些状态的原文事实。

## 提交与出图前审查

1. 区分原文、推导和创作推荐；当前阶段关键未决项记录 unresolved，后续阶段放 deferred。预览可用于快看已冻结的身份设计，不能把意外出图当成无须审批的新事实。
2. 提交阶段稿时检查当前分域，最终 V2.5 合成卡检查完整字段和专项成果；结构检查不能判断理解或美感，主控逐句问“可画在哪里、怎么连接、与谁不同、依据是什么”。“清秀、利落、质感好、结构清楚、自然垂落”单独出现仍属缺项。
3. 当前阶段 Markdown 写成连贯设计段落，附关键人物依据、实际专项成果、近邻比较和重要待审项；不要把六组观察维度变成问卷。JSON 与 Markdown 同样具体。
4. 提示词按画幅提取**可见**锚点。头像不强塞鞋和背面，完整细节留在设计卡/全身/执行表；每次只强调少量识别锚点，避免相互矛盾或过度堆词。旧卡若不够具体，先补设计，不擅自在出图阶段创作。
5. 身高、体重和“瘦高型”不是视觉比例方案。新提交的人形身体阶段及 V2.5 合成卡按[焦点与三维形体交接](feature-focus-and-body-form.md)给五组比例锚点；至少头身用明确数值，其余可用可定位的骨点关系。检查正面、侧面、背面和服装遮挡后是否仍是同一骨架。示例比例仅是待审提案，不作为全剧默认人体模板。
