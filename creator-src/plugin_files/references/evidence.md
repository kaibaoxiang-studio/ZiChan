# 剧本依据与决策边界

## 三份输入的职责

标准化剧本是事实依据；资产表提供稳定角色 ID、别名、层级、状态和索引；场记表可选，帮助核对表情、镜头与出场语境。三者冲突时列出每个说法与来源位置，暂停受影响的设计选择，由操作者决定。不要以资产表或成图悄悄覆盖剧本原文。

输入优先读取 JSON；没有 JSON 再读 Markdown，最后读 Excel。Markdown 与 Excel 的行号、工作表及行号是溯源位置。原件、转换文本和文件 SHA-256 保持关联；无法读取的字段写入疑点，不凭空补齐。

## 四类陈述

1. **原文事实**：可指向剧本原文段落、场次或标准 JSON 的 `source_refs`。写成 `facts[{text,source_refs}]`。
2. **保守推导**：由已有事实与生活/制作逻辑推得，记录 `basis_refs`，明确“推导”而非原文。
3. **创作提案**：世界观与人物需求导出的外观方向，尚未获选时留在候选，不进入最终提示词。
4. **已批准选择**：操作者定稿的发型、体型、服装等，写明理由、确认人和版本；它可填补空白，但不得改变剧本明确事实。

参考图也要拆成具体优点：身份结构、服装裁剪、材质、配色、风格或气质。记录要提取哪一点；没有明确许可或决策，不把整张图的性别、职业、体型、年代和背景一起照搬。外部成图产生的新细节先放在 `adoption_proposals`，操作者批准后再更新设计卡。

## 证据守护检查

- 角色 ID 与资产表一致，别名不能合并成另一个人；主角和重要角色走深度设计。
- 每条原文事实有非空 `source_refs`；外观禁忌与身份不变量也有来源或明确的批准记录。
- 角色状态只在换装、年龄阶段或明显外观变化时建变体。轻微脏污、短暂情绪或单场动作不自动变成新角色资产。
- 作品整体画风与角色个体外貌分别审批。确认“大画风”不等于确认每张脸、体型和服装。
- 上游文件更新后先做影响审查。资产表角色记录变化可直接定位；剧本或场记变化的影响不明时，保留待决状态并阻断发布，直到操作者列明受影响角色或全剧视觉基准。

证据不足时输出可回答的问题。不要以“可能”“一般来说”包装为确定事实，也不要把课程里的模板人物当作剧本人物。
