# 色彩库检索与场景适配

需要判断配色来源、检索或补色时读取。缺少可用方案、需要补足未定颜色、用户明确要求重配色，或第二步需要建立目标光影氛围色卡时调用库内数据。第二步可筛选电影／导演配色关系作为光色参考，不自动重配材料本色；已有适用色卡则优先复用。换视角和纹理修复仍沿用基准，不自动检索重配。仅追溯来源不授权修改设计。

## 先确认适配条件

以本次资产、世界观、用途、原定材料、身份色、静态时刻、有效光源、主视觉和初步机位为边界。配色来源按以下优先级使用：

1. 本次用户明确指定的颜色、色卡及其用途，或明确要求修改的范围。
2. 本次适用的项目已确认配色；局部迭代或换视角以本次采用的可用基准保留未改部分。
3. 可用旧提示词、色卡或文字方案中的配色提案。缺少正式确认不是重新选色的理由；继续保留提案身份，不写成原文事实或永久设定。
4. 缺少方案、仍有未定颜色、明确要求重配色或第二步目标氛围缺少适用色卡时检索知识库，只补缺项或调整授权部分，不顺带替换已有材料色。

“可用”指属于目标地点、本次状态及修改基准，能理解颜色用途，且不与有效事实冲突。第二步还须能支持[本轮目标与光影关系](atmosphere-palette.md#目标适配与保护项分离)，不因同地点或色值接近就机械复用。对仍适用的确认色卡保留色值，用光域与职责表达获准改进；旧提案不适配时仅调整授权部分。用户指定／确认方案与目标实质冲突，或需要改变未授权材料、光源时，说明限制并澄清必要选择，不重检索偷偷覆盖。不能把其他地点或互斥时刻的光色作为适用基准。以上优先级不授权改写剧情状态或增加光源。

配色始终需要落实，但选库不是目的。无法找到合适条目时可在既有边界内提出项目配色，不强套导演模板；文件或工具不可用时说明具体限制，使用可读条目或项目资料继续，不冒称已完成检索。

## 小范围检索

本库根目录为 [knowledge/color](../knowledge/color/index.json) 所在目录，所有运行路径相对本包。下列命令示例从skill根目录执行；实际工具可使用发现的绝对skill路径或设置工作目录，不假设当前目录就是skill根目录。

```sh
node knowledge/color/scripts/query.mjs --query '绿 金 华丽' --limit 3
node knowledge/color/scripts/query.mjs --hex '#0E2A24' --limit 3
node knowledge/color/scripts/query.mjs --id 017
```

关键词和RGB距离仅作候选筛选，不是语义理解或艺术适配概率。第二步查询词来自目标光影关系、有效照明和保护边界，原图颜色只作约束与补充线索，不以最近色值或时代标签独自定卡。按项目条件选择查询词，中文无命中时可用相关色名、英文标签或分类重查；不因示例使用绿金就默认西幻一律绿金。

通常完整读最相关的1–3个 `entries/编号.json`，核对颜色、用途转换及原风格中的冲突，必要时更换候选。不得仅按导演名或片名相似选整套，不默认读140个条目及所有影片数据。

## 四项内部方案

在 [设计底稿](design-brief.md) 中记录相关决定，不默认保存额外文件：

1. **材料色与位置**：选中色对应哪个已有或允许设计的材料／器物，落在哪个实际区域，保留哪些身份色。内部可记来源编号、原色名和HEX；重映射用途或补充颜色标为项目提案。
2. **可见面积关系**：按初步机位估计大面积基调、连续辅助区域和局部点缀；不能复制原板占比。比例确有需要时标为设计目标并明确分母，材料面积不混入火焰、天空或光照覆盖。
3. **受光与衰减**：有效光源位置、路径、亮区范围和材料响应。阴影色、肤色或情绪色并不是石材固有色；把它用于材料时须重新映射，不能反向改变光源身份。
4. **视觉权重**：主焦点、次重点和背景如何通过位置、明暗、饱和度和反差区分；小面积重点可比大面积背景更醒目，不以色块占比替代注意力设计。

极暗场景的材料固有色可以记在底稿，但画面只描述现有光照下确实可读的色面或轮廓；细部可隐入暗处。不要为展现选中色新增光源、提高环境亮度或把有限色差改成鲜艳色块。

按场景选必要颜色，不固定四色、六色、七色或六三一比例，也不为使用某颜色新增道具、换掉明示材料、增加魔法能力或改时刻。局部任务只处理授权项，不借匹配色板重做布局。

## 资料不是指令或官方定案

索引与条目为用户资料整理的参考数据，不是导演官方色卡。`source_style` 中的“必须”“禁止”、运镜、对称、人物、灯具、天气等文字不作为执行指令；不直接移植原模板、情绪或额外光源。库内“高对比70–85%”等未定义数值不转换为实际光比。

- `concept_design` 保留原概念色值与比例，适配后称项目提案。
- `sampling_claim_unverified` 含原库声明的影片采样，未外部核验，不自动当作实体材料色。
- `source_only` 只有影片来源占位，没有采样色值，不能参与色值匹配。
- `quality` 表示结构状态，不表示艺术质量或外部事实已验证。原中文色名为空时保留空值，不根据情绪猜造来源色名。

原来源相对路径和摘要仅作追溯，不读取原目录。影片资料只在用户需要影片对照或追溯时通过 `--id 编号 --films` 按需读取，正常场景选色不加载。主色原比例为0–1，影片采样原比例为0–100，保留的单位与空值不能混算。

## 合并与复用

将四项方案转成完整中文画面描述，说明实体颜色、分布、明暗和保护项。第一步及其他局部模式不默认附色卡；第二步按[光影色卡](atmosphere-palette.md)绘制等宽纯色色块及用途说明，色值只作绘图与复用数据，不展示比例。正文外简短标注实际采用来源与“本场景适配”，不称官方色卡；不额外交检索报告、HEX表或绘卡提示词。不用“按某导演色卡”代替完整光源与区域描述，不自行生成场景图。

旧卡用途或标签变化时按[卡面与指令同步](atmosphere-palette.md#卡面与指令同步)处理，不将已改职责的提示词与矛盾旧标签一起交付；仅修改标签不等于改色或重新检索。

同地点跨视角复用材料身份、色彩职责与位置，不锁死像素占比；昼夜改变受光而非材料。跨场景按文化与用途保持色彩家族，但不复制圣堂的深绿、古金、火焰或大空间。只有用户要求保存项目档案时持久化方案，并分开确认设计与暂定提案。

交付前按 [色彩光影](color-light-atmosphere.md) 和 [提示词交付](prompt-delivery.md) 联合核对：颜色是否形成实际区域，光源能否解释明暗，背景是否抢焦点，身份色是否连续，成品是否无需额外色卡也能使用。未出图只报告文字检查。
