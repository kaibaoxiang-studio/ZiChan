# 连续流程验收条件

在[执行输入](chain-inputs.md)的实际输出保存后读取，不提供预期文案或强制匹配措辞。检查真实关系、来源身份与文件，而非是否出现标题或关键词。它是文字链路测试，不验证成图、像素保留或空间实测。

## 各步验收

本合成项目的天气已知：初始阴天对应的阴云条件在 CH-2 至 CH-5 中继续保留，昼夜改变不授权改变云况。每份自足生成稿及恢复所需交接记录须能明确恢复这一条件，不能只靠旧对话、文件名或“微弱天空漫射”推定；后者在不同云况下都可能出现。无需编造云层密度、降水、星月或窗外景物，也不要求把云本身画进室内取景。

| 步骤 | 观察证据与判定 |
| --- | --- |
| CH-1 | v1 完整、自足，CH01 与单一日景正确；近端入口／远端窗、左桌／右近端柜、椅朝左墙、椅背通道、桌远端唯一台灯关闭成立。构件选择有具体加工／承托关系但标为提案，不凭严格清单新增物件，也不靠贵重材料代替设计。 |
| CH-2 | v2 实际沿用 v1 的实体与原主机位；夜晚、原阴云条件、原台灯开启中低亮及微弱天空漫射写全，不新增月光／灯具。光域落到桌面、邻墙或邻近地面并衰减，不整屋泛黄或要求旧阴影不变。记录保留原表天气来源，区分明确获确认的昼夜／开关／亮度与未确认的工艺／具体光域，真实指向完整主稿；图像未提供，免色卡。 |

| CH-7 | 指出窗在远端短墙还是左长墙的实质冲突，并补问采用依据；不按 X 名称／新旧时间自动选边、不合成两扇窗，不把资料不足误判成缺图片。 |

## 检查执行与记录

- 天气反例回放：只有“夜晚、微弱天空漫射”的稿件仍缺原阴云条件；明确写成“晴朗夜晚”的稿件与原条件冲突。两者都不通过本项，不因没有月光束就判天气连续；“保留原阴云条件的夜晚”等同义表达可通过，不要求匹配固定词句。
- 每步保存真实输入／产物位置及采用基准；CH-5 须从记录恢复，而不是把前序对话再贴一遍。连续执行可测文件恢复，不因此称跨会话独立测试。
- 上游失败保留失败稿，依赖它的后续项记受阻或诊断性执行；修正规则后从受影响步骤重跑，不能手写一个正确 v2 冒充链路通过。
- 合成请求中的“我确认”只供本测试判断确认范围，不是用户对真实项目或通用规则的认可。
- 同时报文件完整性、文字链路结果、执行者身份及未运行的图片检查；主执行者自测只说明本次输出符合所检关系，不称独立评测或生成稳定性保证。
