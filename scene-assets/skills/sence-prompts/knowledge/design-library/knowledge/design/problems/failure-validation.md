# 失败诊断与验证记录

性质：评审流程与候选失败假设。下表不是已测试的失败案例集；当前六例的出图、空间实测和独立评审状态仍为 false。项目截图中的问题只有取得图像并核对输入后，才能写成观察事实。

## 症状不能直接等于原因

| 症状 | 需要区分的候选原因 | 下一项检查 |
| --- | --- | --- |
| 空间显小 | 建筑本身小 / 只拍入口 / 前景遮挡 / 核心被广角缩小 | 既定体量、可见跨度与取景范围 |
| 核心存在感弱 | 占画面太小 / 光色融合 / 轮廓碎裂 / 过曝 | 主形、背景、可见承托与细节 |
| 锚点失效 | 重复混淆 / 被遮挡 / 本身会移动 / 场景左右重命名 | 锚点定义与第二视角邻接关系 |
| 材质普通 | 仅有材料名 / 工艺无差 / 节点不可见 | 构件分工与接合落点 |
| 光影灰 | 全场同亮 / 全灰材质 / 无差别雾化 / 输出偏色 | 光源、彩色面积、灰度层级分开核对 |
| 功能不成立 | 装饰封路 / 起身面不足 / 新造无依据出口 | 动作链和连通关系；不可見区域保留未知 |

## 测试一次只回答明确问题

先保存资产约束、单一状态、完整提示词、模型/版本（可获时）、尺寸、参考输入与生成参数（可获时）。选择一个主要设计变量做对照；其余条件尽量保持。随机输出可能造成差异，单张改好不能证明某条规则普遍有效，有条件时对多个结果重复检查。

观察写成“哪个部位发生什么”，判断写成“影响何种用途”，假设写成“可能由什么导致”，三者分开。没有图就是待测；看不清就是未知；发现失败仍可记录已测试，但不能记录为效果通过。

使用 [记录模板](../templates/validation-record.md)。项目记录保存到用户选择的项目美术档案，不自动进入通用库。经允许公开且可迁移的结论，提炼为匿名验证摘要；不带项目秘密、人物身份或未许可图像。模板本身不算证据。

## 三种验证不能互相替代

- 出图测试：验证当前模型/条件下的可见结果。不能证明构造可靠或跨图一致。
- 空间测试：文字走查只是预检；实际空间验证须说明依据（白模、测量等）、动作及未知项。空背景没有人物，不表示椅后净空足够。
- 独立评审：记录实际评审者、材料与范围；作者自己的再检查不冒称独立评审。

索引的 true 表示进行了相应测试，不等于通过。证据说明须写实际范围、通过/失败/未知、局限和报告路径；不得用脚本测试或模板冒充艺术验证。新增设计方案不自动继承旧变体的测试结论。

## 首次真实试验建议

从项目提供的资产表选一项，并读取相关剧本描述和已定画风；先保存不变事实，再选一个允许深化的缺口。首轮检验主形与路线，后续检验锚点换视角、工艺和光色。各轮不强制重写已通过部分。

没有资产表、有效图或模型输出时，停在待验证计划；不把合成文字练习说成用户项目的出图成功。本轮方法深化不自动调用付费生成服务。
