# 内置知识库索引与适配边界

需要追溯资料内容去向或解释适配边界时读取。这里将用户提供的两个中文库及补充光色教程按实际场景任务合并、去重和适配；方法正文均随 skill 打包，不依赖原文件路径，不需要再次索取这些资料。

## 入口与设计方法

任务读取范围统一由 [主入口的模式表](../SKILL.md) 决定，本索引不维护第二套调用步骤。新建或重设计时，事实、空间、造型和色光通过 [内部设计底稿](design-brief.md) 统一；仅修改纹理时不因此加载重设计流程。

资产表控制需要生成的资产条目，不意味着每个门框分段、饰带和相对位置都必须在原文逐字列出。具体允许的造型补全、需确认的设定变化，遵循 [世界观与设计边界](worldbuilding-design.md)；知识库中的方案始终不冒充剧本事实。

## 后续设计体系的存放

用户讨论形成的[日常生活体系](daily-life-system.md)与[世界观体系总览](worldbuilding-systems.md)属于设计方法，放在 references，按主入口读取。knowledge 承载有来源、前提和限制的具体案例／配色数据，方法示例不冒称验证过的案例。项目已确认的技术、组织、地点范围与本轮设施／布局提案按连续性规则分开保存，不写回通用知识库，也不因生成而自动定案。

## 补充光色教程的去向

补充来源为用户提供的《AI视频场景光色与氛围设计_两篇教程提炼》，包含客厅多氛围与医院色板案例。本次依据已读取的提炼稿及嵌入图例适配，不声称直接核验先前暂停的原网页；不复制原图或将其设为强制参考资产。

| 提炼稿中的适用方法 | 内置位置 |
| --- | --- |
| 固定基底、用光照覆盖和亮暗距离表达氛围 | 色彩光影；底稿记录当前光域关系 |
| 带用途的色板、跨场景复用关系及保护功能色 | 色彩光影；底稿的按需色板职责 |

## 五维创作规范的去向

用户提供的《电影场景设计创作规范（核心五维度）》用于重组主入口、设计底稿与验收，不作为新增资产或生产要求。主题分级和人物关系的方法适配在 [叙事意图与人物外化](narrative-and-character.md)，空间戏剧归入走戏与构图，统一美学归入世界观、材质与色光，真实感归入世界观与资产状态核对。

五维用于判断，底稿另保留主体轮廓、材质与装饰分工、状态天气、布局和光源等具体执行字段。主形、布局、取景与光源条件联合设计，再深化工艺和光色。中文生成写法已集中到 [提示词交付](prompt-delivery.md)，原生成文件仅保留 [成像风格与来源参考](scene-generation.md)，按主入口条件读取，不再默认加载或维护第二套流程。

未直接采用的硬要求包括：每场三版状态、固定主题数量、四类镜头和全角度覆盖、工作人员隐藏通道、70／25／5配色、核心物件100%还原承诺、强制生活杂物、两三件私人信物以及性格／阶层对应固定审美。这些需服从资料、用户范围和静态场景用途；不增加分镜、施工、预算或出图工作流。

## 原有适配边界

- 场景范围、名称、状态和条目粒度继续由资产表及用户选择控制。设计方法不能用于提取新资产、创作新剧情或增加交付版本。
- “每图必须有人”改为内部检查人尺度，成图默认无人；利用原有门、家具、台阶等关系表达尺度，不新增人形比例尺。
- “夜景越黑越好”“必须有月光或点光源”不采用。光源和暗部层次服从选定时刻与项目画风；自然夜空反射也能构成夜景。
- 不把固定配色比例、饱和度百分数、风格占比、材料数量、巨物倍数或教学标准尺寸设成硬指标；只保留主次组织和比例一致性。
- 色彩、建筑、天气与情绪的对应是设计选项，不是规律。不得据此判定阵营善恶、角色性格、文化价值，或改写天气与时代。
- 不因“需要生活感”强加破坏、垃圾、脚印、半杯酒或撤离痕迹。维护良好、秩序清晰的空间也可以有身份和美感。
- 天体、悬浮、发光生态、魔法能源须有明确设定或另经确认，不能用一句自编解释使其自动合法。
- 平面图、三视图、日夜天气版本、材质图及三维交付不自动新增；第二步默认附光影色卡，其他模式不自动附卡，只保留本次所需的布局、色彩和连续性信息。
- 三维面数、贴图展开、绘制调用与烘焙不是静态提示词要求；仅吸收远近细节分级和可复用构件语言。

项目已确认设定优先于知识库中的参考方案。新构型、配色与工艺是“本轮美术提案”；用户未确认前不能写成永久设定或原文事实。
