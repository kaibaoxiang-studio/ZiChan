# 场景视角与局部修改规则

审查实际成图反馈，或对同一资产的已有场景图／已确定设计进行视角调整、局部修改、纹理修复时读取。以目标资产标识、可靠当前基准及审查问题或修改要求为输入，保持原资产对应关系；不要求每轮重新提供完整资产表。仅审查时，对照图像、原提示词及有效资料解释问题来源与修正方向，不据此自动修改文件、重写成品或调用图像服务；用户要求修改后，再按授权范围执行。身份或状态有实质歧义时按资产输入规则补充相关资料。

## 修改范围

基于已认可场景图、目标主要是光影氛围的请求，走[第二步氛围重新打光](atmosphere-relighting.md)，不按完整场景重设计处理。本文件继续负责共用基准与修改边界；交付用[二次打光写法](atmosphere-relighting.md#第二步二次打光提示词)。重新打光时保留实体与机位，不把原阴影／反光列为不变项；昼夜、灯具开关和光源变更按本次授权处理。纯纹理修复、换视角不因此自动进入第二步。

有实际成图反馈时，按下方[反馈诊断与修正](#反馈诊断与修正)对照依据后再决定修改范围，不默认以增加细节或加长全文解决。重新生成可更新授权设计；局部编辑继续保留未授权的布局、机位与状态。

识别作为基准的原图、当前版本、修改目标及需保留的设定。沿用已有底稿；没有底稿时只记录本次所需锚点，不为局部请求重建全套设计。底稿的暂定方案与用户确认项继续分开。没有原图时，可以优化文字方案，但不能宣称已经检查或编辑图像。

局部修改以实际可用的图像或文字版本为基准，优先一次解决一个明确问题，列出所有与这次修改相关的保留项。用户明确要求多处关联修改时按其范围执行，不机械拆成多个任务。若问题需要整体布局、建筑结构或画风重做而超出授权，说明限制并请求方向；获准后按当前资产重新设计，不伪装成微小修改。

世界观统一或强化场景特征时，遵循项目已有美术约束；文化、技术或补全权限不清时，按需读[世界观与设计边界](worldbuilding-design.md)。用户已授权改变场景概念或核心造型时，读[主动美术设计](art-direction.md)，在该范围内更新此前设计，不把失败造型锁入保留项。未涉及的资产事实与空间关系继续保留。

深化材质时读取 [材质与工艺设计](material-and-craft.md)，区分纹理修复与构件、包边或拼接的造型调整。用户要求解决走戏功能或重新安排空间时，读取 [走戏空间规则](staging-layout.md)，允许在授权范围内调整家具关系并说明对固定锚点和既有版本的影响；不要同时要求全部旧位置不变。仅换材质时不借机重排布局。

按 [交付格式](prompt-delivery.md) 的基准类型选择成品：有图时交完整编辑指令并说明需同时输入的基准图；无图有旧提示词时交合并后的完整生成提示词，不以“沿用原基准”代替未改部分。完整文本回写不等于重新设计，仍只改获准内容。旧稿状态假设按资产输入规则保留待确认身份。不能宣称文字能保证像素级复刻或百分之百不变。

## 反馈诊断与修正

先分清用户提供的是基准图、待检查成图、原提示词还是文字反馈，沿用其指定版本与检查目标。仅凭“图有问题”的文字不能声称已看图；缺成图时可检查提示词并讨论用户报告的问题，缺基准时可描述成图可见现象，但跨版本移位、缺件或状态不一致只标“无法对照”。只补影响本次判断的资料，不要求全项目表或固定的反馈问卷。

按固定实体与关系定位问题，例如“桌窗侧通道被柜体占用”，而不是只用“画面左边不好”。区分原图的可见事实、有效设定、本次图像观察与推断；透视缩短、遮挡和出画不自动判为缩小、删除或移动。具体反打对照沿[实际图像检查](verification.md#第三步多角度与反打回归)。

| 有证据的问题 | 判断与下一步 |
| --- | --- |
| 必要功能、布局或机位在文字设计中遗漏／自相矛盾 | 设计或提示词问题；指出缺失的具体关系，在获准范围补足或纠正，不添加整套无关细节 |
| 提示词及有效基准已经明确，而成图漏画、错位或构造穿帮 | 输出表现与指定设计不符；针对实体区域和正确关系写修正，不能据此断言模型能力或所有原因 |
| 参考之间矛盾，或关键背面、道具时刻没有依据 | 先处理采用版本／未知项；不把猜测定案，也不靠修图掩盖资料冲突 |
| 只是不符合新审美目标，但符合原设计 | 区分新偏好与生成错误；重新设计还是局部调整取决于用户本次要求，不默认推翻认可基准 |

同一问题可能兼有文字遗漏和输出偏差，分别说明证据，不强行只归一类。仅审查时交具体发现、依据和建议方向，不自动改写成品或落盘。用户要求修改时，确定本轮目标及正确关系，交一条相应的完整提示词；保留项排除已获准改动，指明所用实际基准。不能实现目标而必须移动原物、扩大房间或改变机位时，先说明取舍，不冒充只改纹理或细节。

后续用户提供新结果时，先检查原问题是否改变，再检查修正可能影响的邻接、遮挡、光影和保留项。不以“原问题没了”判整张图通过；重复失败时重查基准、指令歧义与目标可达性，不自动叠加负面词、换模型或调用服务。是否保存按用户要求执行；认可的局部结果只覆盖其明确范围。

### 可选反馈记录

用户要求跟踪迭代时，在项目记录里保存“问题与实体区域 → 依据图／稿及版本 → 观察、推断或用户报告 → 本轮修正与保留范围 → 新结果及是否复核”。没有新图时结果写“已交文字修正，成图待核验”，不要写“修复成功”。可以与[轻量交接](continuity-record.md#轻量阶段交接模板)合并，不另建重复日志，不默认写入通用技能知识库。成图中的错误关系不能因为被记录而成为新设计事实。

## 删除与填补

用户明确要求移除物件，或授权纠正图中／旧提案中无依据的物件时，修改提示词可直接要求删除，并说明其后方或下方由什么填补。例如：“移除错误加入的右侧路灯，原位置接续同一面砖墙和石板地面，墙面纹理、透视与光照连续。”不能为了构图自行删除原文明示的在场物件，也不改动原表条目。避免留下空洞、重复物件或不合理阴影。

## 同一场景换视角

阶段基准、反打选角、空间推导、未知区域与光影连续性统一按[第三步多角度与反打](scene-multi-angle.md)执行，正文统一按[简洁交付](scene-multi-angle.md#第三步多角度与反打提示词)转写。仅换视角时无需同时读取两套相同规则；本文件负责另有局部修改、状态切换或成图修正的范围判断。

用户明确要求已有日夜、天气或事件状态的切换时，将固定结构、实体色与当前条件分开：保留前者，更新有效光源、积水积雪等实际状态以及发生了变化的物件。不能要求日夜图看起来颜色完全一样，也不凭状态变更增加资产表外的新版本。需要色光方案时读取 [色彩光影](color-light-atmosphere.md)。

同轮既换角度又修改实体时，明确列出获准变化，再用更新后的固定关系推导机位；不能同时要求这些实体的旧位置完全不变。模型专用格式仅在用户采用对应流程时适配，仍先推导真实布局，不改变空间连续性。

## 局部修改模板

以下模板仅用于有基准图的编辑任务；完成后交付完整中文指令，并在正文外标明需同时输入的实际基准图。它可以不重复全房间描述，但不是脱离图像仍可还原场景的纯文字生成稿。无图时按交付格式合并旧提示词全文，不套“以原图为基准”。

```text
以【原图】为基准，对【当前场景资产】进行【一句话修改目标】。

修改内容：
【具体目标、准确区域、修改后的形状、材质或光照；删除物件时说明填补内容】。

完整保留：
【与本次修改相关的建筑结构、门窗、墙面、地面、家具、道具及空间位置】；
【不在修改范围内的相机视点、取景范围、透视、光源和已有阴影】；
【不在修改范围内的配色、反差、颗粒和统一美术风格】。

仅修改：
【再次明确这次修改范围】，其余区域沿用原图和已确认设定。
```

若本次目标就是改变机位、光源或配色，相应项目不应同时列入“完整保留”。保留对象按实际修改范围填写，不复制互相矛盾的模板指令。

## 纹理修复

纹理修复针对已经完成的场景图或已有文字基准，明确需要改善的墙面、木材、织物、石材、地面等表面，补充合理的纹理、粗糙度与使用痕迹。保持构图、结构、陈设、边界、光照和实体配色；表面反射可以随粗糙度改善，但不新增光源或换材换色。构件分块、加包边、改轮廓属于局部设计，不伪装成纹理修复，也不借修复移动物体、改建筑或重做画风。

若用户同时要求改变物件造型或布局，按局部修改处理，不套用纯表面修复的保留范围。

## 模型流程与检查

LIRA 的模型分工、专用写法与来源参数统一在[模型参考](model-reference.md)维护，仅用户采用该流程时读取；否则按用户指定模型或通用写法处理，不自动换模型或调用服务。

交付前更新底稿的相关项并检查：修改目标与保留项是否冲突；删除区域是否有合理填补；新视角是否保持基准空间布局；补全及状态是否有效；资产 ID 与版本是否对应；有图编辑是否说明基准图依赖，无图生成稿是否完整合并而非引用旧稿；是否把尚未发生的图像修改说成已完成。
