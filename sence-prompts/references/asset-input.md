# 资产输入与依据

首次处理完整资产表、重新匹配剧本或判断当前场景状态时读取。本文件只确定资产对应和有效环境信息，不从剧本提取新资产。

## 识别输入结构

接受用户已有的表格、文本表或其他资产清单形式，识别 ID、名称、类别、描述、状态和关联场次等字段，不要求固定列名。仅处理场景类条目，人物和独立道具不另生成提示词；这些条目可用于核对场景中物品的归属与在场状态。

保留原表 ID、名称、顺序、行与子场景粒度。原表没有 ID 时，以原名称或行号定位，不编造原始 ID。表格有合并单元格时，依据实际合并范围理解父级 ID、名称等字段；不能把合并区域的空格误判为新资产或信息丢失。子场景行继续独立对应原表，不因共用父级 ID 而合并输出。

用户指定单一场景或部分条目时只处理该范围。不把“完整资产表”理解成每次必须生成全表，也不因一个条目未出现在所给剧本中而删除它。

## 批量处理与共用依据

一次核对完整表及有效的共用设定，再按目标条目分别确定状态、补全范围和必要资料。共用事实可以复用，单场景的道具、光源例外、使用者倾向或暂定设计不扩散到其他条目。

某条目存在关键未知、版本冲突或文件不可读时，标明该条目及最小待补项，不生成依赖假设的正式稿；其余具备独立依据的条目继续按原顺序交付。保留受阻条目的原标识，不删除、合并或编造替代 ID。若冲突涉及共用世界条件或关联布局，则仅暂停真正依赖该条件的条目，不能自行选边。

新建所需完整表仍须可读；不能把零散目标片段当作已经核对的完整表。用户明确要求整批必须齐备后统一交付时，遵从其要求，先完成可独立的内部设计并一次列出必要缺项。问题澄清后只补或更新受影响条目，不重做其他已交方案。

## 匹配对应剧本

按原 ID、名称、已有别名或关联场次定位当前资产。多个场次出现同一地点时，可以汇总其长期固定的环境事实，但不能把其他地点的设定移植进来。名称不同且没有明确对应关系时，列出候选或澄清，不自行认定两个地点是同一资产。

已有完整剧本时，可理解其中的共用世界观，但仅丰富本次目标资产。只有片段时不声称已核查全剧；表内环境描述已充分时可直接生成。

已写明的进出、接近坐席、取物、转身或互动等，可转为当前场景的静态功能布局条件，按 [走戏空间规则](staging-layout.md) 处理。这不是从剧本提取新资产，也不将人物和动作直接写进无人图。

区分以下信息：

- **资产表事实**：原 ID、名称、条目粒度、已有状态和环境描述。
- **剧本补充**：对应地点明确出现的建筑、陈设、材料、光源及状态变化。
- **用户已确认设计**：已有美术档案或用户明确认可的设计决定；继续沿用，但不称为剧本原文。
- **视觉补全**：为成图而设计的构件、造型、材料连接、配色或相对位置，标为“本轮美术提案”；与既定事实不冲突时可主动设计，不要求原文逐字列出所有细节。
- **冲突或待确认**：不同资料间的矛盾、身份歧义、关键结构缺失或互斥状态。

资产表控制处理范围，不代表其所有事实自动覆盖剧本；剧本也不自动覆盖原表。用户已明确指定采用版本时按其选择执行，否则说明会影响画面的具体冲突。依据只需场次、表内位置或简短说明，不整段复制剧本。

## 基础需求三分法

完成来源与状态核对后，将目标场景整理为明示事实、功能推导、设计空白，不先另写一版丰富细节的原文。

| 类别 | 内容与后续职责 |
| --- | --- |
| 明示事实 | 原资产身份、已有建筑和材料、陈设、单一状态及有效光源；保留来源，按冲突规则处理 |
| 功能推导 | 从已有调度得到可达、停留、操作、互见与遮挡等必要关系；这是使用约束，具体位置、比例和构型未定时不提前锁死 |
| 设计空白 | 未定轮廓、普通相对布局、比例、加工、连接、装饰与配色；留给主动美术设计，不因缺少逐字描述就停止创作 |

例如原文“穹顶下圣火、高台、台阶，人物走到圣火前”，基础需求是保留设施及入口到圣火前的可达关系、所需停留面；金色火盆、柱数、踏步数与火形均不能在整理时变成原文要求。这是方法示例，不是所有场景的结构模板。已确认项目设计另行保留，不重置为未知。

关键剧情物件在场时刻、隐藏空间或特殊能力未知属于待确认，不属于普通设计空白。功能推导不新编动作；无人图描述支撑动作的环境，不画角色和路线标记。

## 选择静态状态

优先采用用户明确指定的剧情时刻和原表已确认的状态。表内已有昼夜、天气或破坏前后条目时，分别处理并复用固定锚点，不自行增加条目。

同一条目跨越多个场次时，将永久结构与事件状态分开：

- 固定结构：墙体、门窗、固定书架、主要家具及长期挂置物等，可跨场次确认。
- 事件状态：角色携入容器、洒落液体、损坏物件、掉落饰物等，仅在选定时刻确实存在时描述。
- 临时光照：特殊魔法作用、火光变化、雷电等，不能因在某个事件中出现就设为房间常态。

角色手持或尚未携入的物品，不自动摆在空场中；已移走的物品不继续保留。无人图仍保留该时刻应有的文件、家具、痕迹或杂物。

未指定时刻且没有实质差异时可交付常态环境并说明用途。存在会改变画面的互斥状态时，澄清必要选择；用户允许探索稿时可明确写出暂定基准，不把它说成已确认，也不将多个状态混成一张图。

关键物件的在场、缺席、携入时刻、破坏前后或特殊光照若缺少有效依据，归为“剧情事实待确认”，不以“本轮美术提案”自行决定。某物在同场后段出现，不足以确认它在较早时刻已摆入环境；未知也不等于不存在。先询问会影响目标画面的必要事实，不靠正文外一句“待确认”就交付含该假设的正式提示词。用户明确允许在该不确定状态下探索时，先标明“探索稿／非定案”和具体暂定时刻，再生成单一状态的方案。

迭代时继承事实的来源和确认状态，不仅继承旧文字：曾经出现于旧稿、基准图或测试中的假设仍是待确认项，不能改称“既有”或“已确认”。仅修改光色、纹理时也不擅自确认、添加或删除这类物件；未受影响部分可以继续处理，但依赖未知状态的完整正式稿须待确认，或经授权作为探索稿交付。普通造型提案的许可不涵盖剧情状态推定。

## 缺失信息

首次建立项目或新建场景没有完整资产表时请求用户提供，不启动资产提取流程。已有可靠基准的局部迭代不重复索取全表：核对目标资产标识、采用版本、当前状态和修改范围即可；若相关事实无法从基准或项目记录恢复，只补充影响本次任务的资料。不能用某张无来源图片替代新建项目的资产核对。

文件无法读取时说明受阻范围，并请用户补充可读格式或相关表格内容，不冒充已读取。

资产身份、画风或时代、剧情依赖的关键入口和房间边界等缺失且会实质改变设计时，只问必要问题。普通造型、构件、装饰、配色、工艺和未定相对布局可按世界观的设计补全边界提出提案；不把精确尺寸当成测量事实，不新增重大建筑功能、密道或魔法能力。仅因为家具朝向未写明，不必暂停整个方案。

不要求先提供平面图。仅在剧情依赖门窗、通道、遮挡或隐藏空间时明确这些关系。模型和画幅未知不阻塞通用中文提示词，未指定的设置保持未知。
