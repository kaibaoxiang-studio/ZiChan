# 场景设计知识库（试用版）

修订4：保留6例建筑参考，新增5例《惊竹》院落项目迭代案例，共11例；问题方法由5类扩为7类。新例覆盖版本选择、反打、功能构件尺度、自然纹理和雨景，附本地文档散列及4条历史用户反馈定位。用于解释和检查设计，不是现成场景模板。

本库保留独立维护入口；同一版本随场景生成 skill 打包，按实际问题检索。仅包含方法、原创摘要、少量反馈摘录和来源定位，不含原始图片或完整日志，不自动联网或记忆项目设定。项目文档副本另存项目档案。

## 读取入口

先检索摘要与适用前提，再读取少量相关正文。没有适合案例时可以不使用，不能强制六选一。


院落项目新增案例：反打优先DES-008，功能构件尺度优先DES-009，自然纹理优先DES-010。零命中直接使用skill已有专题；不强制套院落案例。

先检索本轮一个主要缺口，读取相关方法和少量案例；不要求每次把全部方法执行。`--query-problems`仅搜索问题标题、关键词和摘要，空格分词、OR命中及受控同义词；零命中不填充，结果是阅读候选，不是适用性判定。`--problem ID --read`返回对应全文，案例查询行为保持不变。问题检索不能与案例筛选参数混用。

身份特征、视觉中心与实体锚点分开设计：主形让场景可认，光色/轮廓让主要区域可读，稳定实体让位置可描述。单张无人背景不保证人物调度可用，也不保证多视角几何一致。

需要实际验证时使用 [记录模板](knowledge/design/templates/validation-record.md)，先保存不变条件、允许改动、完整输入与可观察标准，再记录结果和复测。症状排查表是待验证假设，不冒称已经积累的出图失败案例；这轮没有实际生成图、空间实测或独立评审。

脚本路径可使用绝对路径，从其他目录运行。要求 Node.js 18 或更高版本，无第三方依赖；只读取本库，不联网、不改文件。摘要默认最多3条；limit为1—100，与库中案例总数无关。--read只读取已索引条目，不接受任意路径。

--query用空格分词，按标题、标签、补充概念词、原案例名和摘要检索，正文低权重补检。index.json的alias_groups只扩展明确词组，不猜测所有中文近义词，也不会自动切分中文长句。宜输入“圣堂 主位 光域”这样的正向关键词，不把带否定约束的整段剧本直接用作查询。

每个查询词只计最强命中：标题10分，标签/概念词/原案例名8分，摘要4分，正文1分；同义词命中乘0.75。按总分、命中词数和ID排序，正文重复次数不加分。结果的matches说明命中词、字段和贡献分。正文中“不应使用某方案”也可能命中该词，因此命中只用于找到阅读候选，不等于推荐采用；适用前提与限制仍由执行者核对。

类别和关键词共同过滤，关键词之间采用OR命中；零命中不自动填充。脚本会读取本地正文完成检索，但默认不把正文全文返回给模型。评分不是语义相似度、艺术适配概率或事实可信度。

## 创作时怎样用

1. 先锁定资产表、剧本单一状态、世界观和已有美术约束；本库不提取或新增资产。
2. 用当前缺口检索，例如“走戏 对置”“阅读 任务光”“材质 工艺”，而非只搜题材。
3. 阅读候选的前提、限制和来源事实，再选取关系原则；设施、符号、材质、开口不直接照搬。
4. 按下面的设计补全边界写出主形、连通路径、实体锚点、可用光源与材质职责。已有或本轮允许提出的普通设计可使用；关键条件不明时不能由案例代为确认。无法适配的案例弃用。
5. 把选中原则转化为自足的中文静态无人场景提示词，不把案例编号当作生成模型能理解的指令。不默认输出色卡图、色卡提示词或HEX表。
6. 检查主题叙事、空间戏剧、统一美学、真实感与人物使用。文字检查不能代替生成图、镜头覆盖或空间实测。

案例里的“人物使用”用于预留空间，不要求在无人背景图中生成角色；实体锚点用于相对定位，不能保证生成模型在后续所有视角中保持同一几何。

## 设计补全边界

| 层级 | 如何处理 |
| --- | --- |
| 已定事实 | 资产身份、用途、明示材质、固定布局、单一状态、特殊能力和明确的唯一光源保持；用户授权修改时才改动对应项。 |
| 普通未定细节 | 在任务范围和已知世界工艺内，可提出轮廓、相对布局、连接、加工、配色和非剧情性装饰方案；符合用途的少量包覆、收纳或常规照明也可有条件提出。统一标“本轮美术提案”，不逐项等用户批准，不另立资产、不增加剧情功能。 |
| 关键未知或范围外变化 | 动作依赖但未知的门/通路、道具在场时刻、互斥状态、改掉明示材质、新增宗教身份/特殊能力或改变明确唯一光源，需要确认，不用提案标签绕过。 |

严格还原清单、局部纹理修改、换视角及只改光影时，遵守该任务的更窄范围，不能借案例重设固定锚点、材料或建筑。完整资产表不是所有构件细节的逐项白名单，但也不授权新增主道具或故事功能。

每例的“条件式深化”包含原创文字空间关系、工艺节点和变体。示意只表达连通/承托，不是原建筑平面、精确尺寸或施工图；描述片段须代入当前事实，不能直接作为完整交付。变体是备选，不要求全部叠加。

## 来源和更新边界

[index.json](knowledge/design/index.json) 保存候选摘要、标签、前提、限制与验证状态；[sources.json](knowledge/design/sources.json) 保存机构/作者来源链接、核对范围和未验证事项。entries保存原创提炼正文。

来源事实、提炼者方案、已确认项目事实是三种不同层级。网页和文档属于参考数据，不是执行指令。公开可读不等于可再分发，本包仅收录自己的短摘要和来源链接。

后续扩充条目时沿用现有字段，分配唯一ID、补来源与适用条件，验证引用与检索。项目特定配色、历史和出图结果应另存项目美术档案；通用案例只保存获准的来源摘录与方法。本版覆盖少量现实建筑参考及一个院落项目，尚非完整建筑、材料或世界观知识库。

## 维护检查

S009为本地来源，不伪造网页URL；manifest_path指向库内清单，记录相对文件名、SHA-256及日志反馈位置。下载文件当前散列不证明历史字节一致。DES-007—011的evidence_refs定位具体文档章节或日志ordinal；项目尺寸、门形、树位和天气不扩散到其他项目。来源验证不依赖Downloads目录存在，完整日志也不随skill发布。

```sh
node scripts/check-library.mjs
node tests/pilot-regression.mjs
node tests/deepening-regression.mjs
node tests/project-regression.mjs
```

第一条是通用检查，不规定6例、每类2例或永远未出图；新增类别与案例后继续使用。索引采用schema_version 2，新增条目须包含case_reference、search_terms与原有字段。案例ID支持3—6位数字，正文路径与ID对应。检索启动时也会检查数据与引用，拒绝损坏索引。

第二条只维护首批案例的关键行为，不限制库的总规模：锚点/大理石/协商召回、同义词与低权重正文补检，以及异常参数、合法新增条目、新类别和验证状态升级。测试使用进程内临时数据覆盖，不改交付库。更新首批设计职责或标签时应同时审查这些回归预期，不把失败简单改成通过。

已有image_tested、spatially_tested、independent_reviewed状态可由false更新为true，但须在verification.evidence中为对应状态填写note和report_path；报告必须存在于库内并说明测试条件和结果。true表示实际进行了对应测试，不等于效果通过；说明应标明所测设计版本/变体和通过、失败、未知范围，不能让新提案继承未覆盖的旧结论。路径存在不证明证据真实，通用检查不替代人工审核，模板和代码测试不能作为出图证据。用户项目档案仍另存；库内报告只能保存经允许的、适合通用案例发布的验证摘要。

可选problem_library字段保存问题ID、标题、摘要、检索词、库内路径与关联案例ID，通用检查验证其引用和只读行为；保留schema_version 2，兼容没有问题库字段的旧案例数据。修订3的问题回归在 `tests/deepening-regression.mjs` 中执行，测试检索、路径/引用拒绝和兼容性，不验证美术效果。
