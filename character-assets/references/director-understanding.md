# 角色设计总控：从理解全剧到具象设计

这是 v0.2.5 的共同方法。总控设在角色资产插件内，负责理解、定位、解析与整合；专项提供设计方法和结构方案。跨资产协作通过可追溯来源、稳定角色/状态 ID 和产物合同预留，不要求安装另一套总控插件。

## 先理解人物，再决定设计工作

收到完整剧本时，先阅读全文，理解故事因果、人物关系、时间顺序、反转和信息释放，再做目标人物的专项检索。不能把搜到姓名的几段当成全剧理解，也不能从资产表身份标签直接生成外形。正文过长时按集、场或连续文本单元分批读，维护覆盖记录；已读片段可以复用，不必每个角色重新全文读取。`context-units` 只提供来源单元与覆盖核对，不替模型阅读、理解或生成结论。

全剧阅读至少能说明：什么冲突推动故事；目标人物在关系网和关键转折中起什么作用；人物前后是否变化；首次出场的观众知道什么、不知道什么。`ScriptContextV1` 保存源文件哈希、全部阅读单元和综合理解；character_index一次轻量覆盖资产表全部人物ID，记录作用、弧线、关系与证据单元，不要求全员先深设计。这样同源上下文可供后续角色复用，避免每画一人重写context使其他人失效。来源变更后复用未变内容，补读变化单元及受影响前后文；不能只沿用旧摘要就宣称新版本已全文阅读。完整来源SHA、阅读覆盖与结构且unresolved为空时，context自动ready，系统审批仅检查阅读声明合同，返回interpretation_confirmed:false；不增加用户额外审批。未决非空须待复核，手动确认可选。结构校验不证明真正理解，人物解释在方向稿集中确认，并用跨场证据与实际设计验收。

只有片段、小传或人物简介时，可以独立分析与提出设计方向：说明阅读范围和缺少的上下文，不伪称全剧分析，不以缺资产表阻止文字工作。无项目且未指定阶段时，默认先做identity/头像，交人物定位、当前身份首稿与关键路由；身体和衣装仅留方向或约束，不要求首稿完成全员详设、全套项目或完整生产JSON。进入正式受版本管理的资产链时，再补齐生产记录、项目剧本和稳定角色/状态索引。

## 用言行与关系检验人物判断

重要判断寻找原文行动、原话、选择与后果，联读相关场次。人物自述、别人评价、旁白和实际行为分开记录视角与可靠性。一个角色被称为“冷酷”，却在无人注视时反复照料他人，不能只截取“冷酷”；要分析外部误读、主动伪装、价值冲突或随剧情变化，并保留无法确定的解释。

区分公开身份、私人动机、当下策略和价值取舍；比较人物面对压力、亲密关系、权力差异与资源不足时的行为。不以单次怒气认定永久性格，不把被迫行为当作偏好。矛盾证据可能正是人物设计的关键。原文不能判定时，提出有依据的推荐解释和确有影响的备选。

人物定位回答：他自己想成为什么人；别人以为他是什么人；他实际如何行动；观众当前应该读到哪一层。弧线区分起点、转折和结局；面孔等身份不变量与可变打理、服装、姿态状态分别处理。后续秘密用于内部理解，但不能因此把秘密符号提前画进首次出场形象。

## 从理解形成设计意图

先用一两句话说明人物设计意图，再展开外形。意图描述观众应先注意什么、保持什么误判或反差、哪些信息暂不显露。默认一套有理由的推荐方案；存在显著改变人物读取的分歧才给备选，不为凑多套制造噪声。直观、反差、隐藏均可服务叙事，不要求角色把所有性格经历写在脸上。

合适的推演链是“原文事实或获选解释 → 实际经历/自我呈现需要 → 功能与审美取舍 → 可画结构 → 来源性质与出现阶段”。长期抬臂作业能影响袖窿、腋下余量和固定，不能证明天生宽肩。预算与护理时间能影响取得、维护、修补和打理，不能直接推出脏脸、低颜值或某类族群五官。无法唯一推演的骨相、头身比等由总控提出原创设计选择，不伪装为必然结论。

六组只是查漏的观察镜头，不是逐项必填问卷，也不是先填字段再找证据：

| 观察镜头 | 理解的问题 | 可能形成的设计工作 |
| --- | --- | --- |
| 叙事、关系与观众信息 | 推动什么变化；与谁对照；什么应展示、反差或隐藏 | 设计意图、主锚点、安静区、阶段变化与避免提前泄露的信息 |
| 性格、选择与自我呈现 | 跨场言行如何一致或矛盾；愿展示、掩饰或维护什么 | 打理、衣装组织、佩戴与常态体态；不将性格直接变成骨相 |
| 世界、环境与可达技术 | 实际接触哪些气候、空间、工具、材料与技术 | 防护、维护、材料和连接结构；不由气候推定族群面貌 |
| 生活、职业与身体行动 | 动作频率、使用方式、居住通勤、明确训练与限制 | 发型固定、活动余量、受力磨损、比例与体块方案 |
| 圈层、经济与资源选择 | 可获得什么、愿花费什么、如何遵守或偏离规范 | 取得与修补、剪裁材料、制服中的个人选择；不以阶层决定美丑 |
| 人生阶段、身份连续性与群像 | 年龄身体事实；与近邻共享或拉开什么；哪个状态改变 | 原创脸与身体选择、身份不变量、变体边界与识别锚点 |

抓住真正改变设计的条件。普通部位也要具体，但不必编造性格或经历解释每一道缝线。

## 主动设计留白，守住剧情边界

原文没写外貌意味着存在设计空间。主动补齐当前阶段需要的脸、发、皮肤、形体和衣装，明确作为创作推荐；不把没原文当成停止设计或全部专项跳过的理由。只有改变方向、身份或剧情的未知才集中询问。已委托细节由总控处理，方向确认与首稿审阅承接这些选择，不逐个毛孔或衣缝申请批准。

分开三种空白：有生活机制的推演；没有唯一因果但必须作出的外观选择；会新增身份、经历、能力或剧情的设定。前两种可主动提出并在方向/阶段稿确认。普通痣、极淡雀斑、自然小幅不对称可随首稿整体审阅，不默认赋予故事来历；显著伤疤、纹身、宗教/组织符号、特殊器官、技术装置和暗示新经历的痕迹须显式说明性质与影响。不能为记忆点给所有人加瑕疵。

资源紧张者可以维护整洁，富裕者可以选择朴素，善意角色可以面部锋利，反派可以没有显著标记。普通、无妆、无首饰、没有新增伤痕均可为完整决定；同时落实其他可画结构。

## 理解后路由 Skill 与知识

先读用户提供的全文或复用匹配来源版本的已有context，再按当前任务读必要知识。打包的references是方法目录，不是要求逐份通读；不要在理解人物前扫描全部规范。总控可以读取相关知识全文，但围绕具体人物问题选择并复用，不机械全读，也不为了省时省略剧本理解。本次使用已有知识，不新增知识采集工程。知识提供方法，不为当前人物提供新事实。

读取 knowledge/reference 是知识加载；执行专项 Skill 是采用其任务方法、产出成果并承担责任。普通任务由主控实际加载和执行专项规范，阶段记录为 `inline`；跨专项矛盾、重要身份取舍、复杂形体/工艺或反复失败需要独立会诊时，真实委派并保留提案，阶段记录为 `independent`。只列名称、复制知识摘要或伪写已会诊均不算执行。交接见 [专项合同](specialist-contract.md)。

交给专项的不是“做发型”，而是人物理解、设计意图、批准锚点、实际行动/维护条件、近邻对照、创作范围和待解矛盾。专项返回结构与取舍；总控负责同部位唯一主责、冲突裁决、焦点控制与整合，不能把十三段独立文字拼成一个人。

## 输出与自检

用户看到连贯的人物理解、定位、推荐意图和当前阶段具象设计，后台记录证据、知识与采用关系。先说明为什么设计成这样，再用实际结构证明；不以字段覆盖率、知识数量或专家数量代表质量。

用反事实检验：关键生活条件、关系或叙事策略改变，哪些设计应改变，哪些身份应保持？只换形容词或完全不响应条件，应回到理解与机制；无关脸型、身高、族群一起变化，则推理越界。只有实际看到图片才报告剪影、遮挡或同框辨识通过。

默认按 [分阶段设计](phased-design.md) 深化与头像快看。旧批准物按兼容规则读取，不因总控升级自动重做。
