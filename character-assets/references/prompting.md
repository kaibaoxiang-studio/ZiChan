# GPT Image 2.5 提示词转换

## 共同输入与输出

只从已批准的 `ProjectVisualBibleV1`、`CharacterDesignCardV1/V2/V2.1/V2.2/V2.4`、对应已定稿图片和当前阶段任务生成 `CharacterPromptPackageV1`。先按[具象描述标准](design-detail-standard.md)检查设计卡：脸部、发型、体态、皮肤、服饰剪裁/材质/色块及配饰必须足以画出已定设计；旧卡只有“结构清楚、自然垂落”等概括句时，先回设计轮提出补细待审，不在提示词阶段自行编造。V2.2/V2.4 卡按 `feature_focus` 主次选择**本画幅能呈现**的锚点；旧卡按已批准的识别轴与身份不变量选择，写入提示词；未见或未批准的自然不对称不得补写。剧本背景、不可见心理和长篇人物小传留在设计卡，不塞进生图提示词。五轴识别特征要落成可画描述；“帅气”“漂亮”“精致”不能代替脸、发和体型结构。未批准的痣、疤、饰品与体型改变不可为了防撞型临时加入。

提示词按“要生成/编辑的图 → 参考图各自职责 → 主体身份锚点 → 本阶段可变项 → 构图与光线 → 关键保留/禁改条件”组织。正向、具体地描述可见结果；只在模型容易混淆之处加简短限制。参考图要编号并说明用途，例如“图1固定面部身份，图2只借服装剪裁，不继承图2的人脸或场景”。不要宣称模型保证百分之百一致，结果必须回流审查。

首版只输出文字提示词和配套结构，不调用图像模型。目标标记为 GPT Image 2.5；快速候选与精修都可用同一设计锚点，但精修提示词要更精确说明改变与保留。官方图像提示指南建议先说明任务、主体、构图、风格与约束，编辑时分别写明改变和不变的部分；实际成图仍可能发生人物和排版漂移。

皮肤、布料、金属、光线与去油控制按[真实质感规则](render-texture-standard.md)按需选取。不要把全套英文正反向词贴到每一张图；若质量问题来自设计卡空泛，先补卡。工具没有独立负面词栏时只写正向可见结果。具体器材名称不会保证镜头物理效果。

## 通用图片方法转成角色提示词

从 `01-通用图片生成` 吸收“任务、输入图职责、构图、原样文字、保留条件”的表达顺序，角色资产的具体应用见[知识快照](knowledge/character-image-prompt/hedgehog-general-image-skill.md)。区分“根据参考图生成新图”和“在目标图上局部编辑”：前者给每张参考图指定身份、服装、风格或版式职责；后者必须单独指出待编辑原图和仅需变化的区域。不要把来源 Skill 的 API、模型尺寸、质量参数或保存路径写进交给外部操作者的文字提示词。

提示词的详略由设计卡决定。若设计卡已经明确外观，只把它整理成清晰的可见描述；若缺关键外观，先回到设计卡请操作者选择，不凭通用示例添加人物、道具、品牌、色板或剧情。取景和身体可见范围要具体到阶段：头像读脸、全身头脚完整、执行表严格四格。人形头像、表情和全身先按[模卡式基础形体图规则](model-card-baseline.md)选择阶段着装；设计卡中的正式服装在执行资产表呈现。风格参考只能控制已指定的视觉形式，不能覆盖角色事实。

图内中文使用“原样文字”区块，逐格写明位置与准确汉字，要求无增删、错字和额外标签。若标签生成为错字，输出回图审查问题与局部修图指令；提示词本身不能代替视觉校验。

## 背景依据与默认处理

背景是独立的视觉设计维度。先查当前图的任务要求、已批准视觉基准和角色设计卡：只有明确指定或获批的场景背景，才能写入提示词；剧本出现过某个地点、用户给过电影美学参考，都不自动授权把该地点或参考图背景放进角色资产图。若需要新的叙事背景，先把具体地点、材质、天气、时间和作用作为提案交操作者确认，再记录依据。

无背景批准的头像、表情、全身和执行资产图，使用**无场景、无纹理、无道具的中性纯色背景**，仅用于分离并核对人物，不代表剧中地点。同期头像候选保持同一中性底色。可按阶段调整照明方向或强度，但不能借“海边晨光”“宫殿火光”“石墙虚化”等光线或背景措辞暗加地点、天气、建筑或地貌。若用户已明确指定背景，遵循其要求并写明来源，不强制改成中性底色。

在 `prompts[].text` 里单列背景依据与可见边界；`acceptance_checks[]` 检查是否出现未经批准的场景元素。回图时实际核对背景，不能因人物正确就采纳意外生成的环境。

可复制到 `prompts[].text` 后按角色填充的最小骨架：

```text
产物：<头像候选 / 九宫格表情 / 全身模卡 / 状态服饰设计图 / 执行资产图>；用途：角色制作参考。
身份：<仅写设计卡已批准的可见脸、发、体型与标记；正式服装锚点只在执行阶段写入>。
参考图：图1=<身份锚点，只取脸和标记>；图2=<按需指定服装/风格/版式，只取获批准的部分>。
当前允许变化：<本阶段唯一新增或变化的可见要素>。
构图：<取景、角度、身体可见范围、格位>；光线：<已批准或不暗示场景的核对用照明>。
背景：<写明批准来源及范围；若无批准，写无场景、无纹理、无道具的中性纯色背景>。
图内文字：<如需要，按格位逐项给出原样中文>。
保留/禁改：<身份、设计卡、其他参考职责边界及不应新增的要素>。
回图核对：<本阶段能够从图上检查的 3–5 项>。
```

头像的 2–3 条候选共用同一“身份、参考图、保留/禁改”，只在允许变化行区分取景、微表情或光线。表情、全身与执行表各自继承当前获批准图片的 SHA 锚点，不复用过期图。更完整的角色阶段例子仍以 `references/expression.md`、`references/execution-sheet.md` 和设计卡为准。

## 参考图职责与风格边界

新增素材中“动漫 PV 角色概念设计”与海报换角案例有可借鉴的方法：**分别标注人物身份、服装、材质、画风、光照、姿态与构图由哪张参考图控制**。在本插件中，已批准头像和设计卡控制人物身份；其他图只提供操作者指定的可见优点。风格图不能把它自己的角色、道具、色板和动作带入当前角色；海报图可启发构图或灯光，但不能自动更换服装。剧情换装必须先在设计卡建立获批准的变体；模卡阶段的中性着装不记为剧情变体，也不作为正式服装参考。

当全剧视觉基准已经批准 2D→3D 时，按[媒介转换知识快照](knowledge/character-image-prompt/hedgehog-2d3d.md)写提示词。人物本体的轮廓、五官比例、发型外形、标志与服装结构继续锁定，材质和光照才是本轮变量。不要把“高饱和动漫 PV 海报”“3D 电影海报”等案例风格设为所有项目默认。资产图阶段优先清晰、可核对的角色信息；戏剧化海报构图只有在操作者另行要求时才提出。

## 阶段要求

- **头像**：画布默认**竖版 3:4**，`aspect_ratio: "3:4"`，每条候选提示词明确写“3:4 竖版”；不得沿用 1:1 方图。人形以脸为主体，完整头部、双肩可见，下沿可到上胸，**不强制裁在锁骨以上**。服装完全不入画时用 `reference_attire: "face_only"`，不能呈现裸体躯干；上胸入画时可直接用 `white_tank` 或 `white_sports_tank` 的白色中性背心，不必先生成无服装入画版。2–3 张候选的取景与着装模式一致；若中途从 `face_only` 改成背心，记录原因并重审整组。只有操作者明确指定其他比例，才记录 `aspect_ratio_explicit_user_override: true` 与 `aspect_ratio_basis` 并改用该比例。同一设计卡给 2–3 条候选，差异限于轻微取景、微表情或光线力度；脸型、年龄、发型、标记和着装模式不漂移。头顶、双耳、头颈及可见肩线留安全边界，竖构图不能截掉身份锚点。外部工具若不能直接输出 3:4，操作者需选择接近的竖版画布后裁成 3:4，并回传最终图供完整审查。
- **表情**：以已定稿头像作强身份参考，读取 `references/expression.md`；新项目默认 3×3 九宫格，只有用户明确选择并记录依据时才用 16 格；给出顺序和图内中文标签。各格继承头像的头肩至上胸取景及 `reference_attire` 模式，不能混用，不引入新的妆容或年龄感。若从 `face_only` 切换成背心，记录原因并重审整张表。
- **全身**：画布默认**9:16 竖版**，`aspect_ratio: "9:16"`，每条全身候选提示词明确写“9:16 竖版”，验收项也核对 9:16。人形按[模卡基线](model-card-baseline.md)穿背心、短裤并赤脚：男角色白色纯色背心与短裤，女角色白色运动背心与黑色运动短裤；不做裸身全身图。只有操作者明确指定其他比例，才记录 `aspect_ratio_explicit_user_override: true` 与 `aspect_ratio_basis` 并改用该比例。用已定稿头像延展完整人物，**头到双脚均入画，头顶、双手与双脚留安全边界**；外部工具若不能直接输出 9:16，选择接近画布并裁成 9:16，回传最终图供审查，不能通过拉长腿或压缩躯干来适配画布。身体比例按设计卡，检查脸部在全身尺度下仍能对应头像。读取已批准的 `body_form.proportion_anchors`，在每条全身提示词的身体段明确复述头高/全高、肩峰/骨盆、同一测量体系下的上段/下段三项关系，在验收项逐项检查头身与腿身。身高、体重、瘦高等原文标签不能替代这些参照。若 V2.2 旧卡缺锚点，先交比例方案供操作者批准并更新设计卡，不在提示词环节猜数；CLI 会阻断新的全身提示词提交。
- **服饰设计图**：在头像、九宫格和全身模卡均批准后，每个资产表状态单独一张，按[服饰阶段规则](costume-design-stage.md)写衣装、鞋履、饰物、妆面状态、前侧背结构与材料；`variant_name` 对齐资产表，三个基础图 SHA 都入 `anchor_images`。
- **执行资产表**：用已定稿头像、表情与全身图作身份、表情和体型参考，**正式服装及鞋履以本状态已批准服饰设计图和设计卡为准**；不能继承模卡背心、短裤或赤脚。读取 `references/execution-sheet.md`；人形严格指定四格、上下占比与左下无头裁切。非人读取设计卡中获批准的替代布局。

每个提示词包附 `reference_images`、非空 `acceptance_checks`、`design_card_sha256` 和 `anchor_images`（阶段名到当前已批准图片 SHA）。新人形头像、表情和全身提示词包还须填写 `reference_attire`，每条提示词与验收项均写明模卡着装；例外方案记录依据。单独全身图明确 `head_visible:true`、`feet_visible:true`。不能用新的提示词覆盖旧版；只有新设计卡或已批准图片才可改变锚点。

v0.2.4.1 的世界环境和技术影响先在设计卡 `world_influences` 获批，再只提取当前画幅能看到的痕迹、装备或材料；面部稳定标记从 `facial_surface.stable_marks` 贯穿头像、九宫格、全身和后续图，施加妆面按已批准状态使用，临时伤妆按场次起止使用。提示词不得把知识库中的群体外貌映射或性格妆容公式当成角色事实。每张服饰图与执行图标明当前状态 ID/名称和其唯一服饰锚点。
