# 本次交付路由与整合

从请求和材料确定人物、状态、所需阶段及保持项，不新增内部模式问卷。默认一个整合方向，普通细节自行决定；硬冲突、重大剧情新增或改变已批身份才集中问。

| 请求 | 起点 | 当前终点 |
| --- | --- | --- |
| 讨论具体问题 | 现有材料与该问题 | 具体判断，不冒称完整提示词 |
| 新角色/完整四类 | 理解人物→采用相关方法→直接设计入词 | 一份文档的头像、表情、全身及各状态执行词 |
| 当前阶段/局部修改 | 当前文档与相关原文 | 完整阶段词/受影响条目更新；其余原文保留 |
| 成熟稿要词 | 复核可画结构 | 直接整理，补真实缺项，不补旧方法证明 |
| 正式生产/旧typed调用 | 真实工程与既有合同 | 真实记录、图像审查和用户批准，不静默降级 |

普通提示词就是设计稿，按[文档合同](prompt-document.md)保存。不前置project.json、资产表、全员规划、长稿、typed design、body_form、专项证明或freeze。独立人物用本地subject；只有真实工程才沿用正式ID。四类是用途而非四方向；单阶段不先做剩余，完整委托不缩成头像。

普通任务携旧project_root/parent_refs时只读当前约束，试改保存独立文档，不submit覆盖active、不使旧图提前失效。错误工程路径报错。成熟稿和同版本理解可复用，来源变了才补读受影响处；缺记录名不自动变成用户材料清单。

人只用同一文档与实际图片；JSON/TXT/来源/版本由工具派生，不要第二份模型手写设计台账。用户明确只对话时仍交完整词，不能把prompt降discussion。文件完成须真实正文与对应文件，程序通过不证明美感或看图。

内部delivery_contract:prompt_document是普通默认；明确正式目的、旧scope或typed输入走legacy_typed，才读[工作流](workflow.md)、[阶段](phased-design.md)与[专项旧合同](specialist-contract.md)。speaking_extra/ensemble按[群演合同](group-ensemble.md)每状态单图，非人按给定形态。候选词无正式图可完成，正式采用由用户人工确认，可走实际人工批准分支，不强制模型审图报告。
