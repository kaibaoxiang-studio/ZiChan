# 本次交付路由与整合

先从请求和现有材料确定对象、用途、当前范围、要交的成果与已有决定。不新增必答的模式问卷。提供全文需要人物综合时实际读或复用有效context；局部只读相关语境。完整人物不默认缩成identity，只有头像就不扩全身。

| 请求 | 从哪里开始 | 本轮终点 |
| --- | --- | --- |
| 讨论／比较某个问题 | 回应具体选择、机制和影响 | 有具体判断及未决边界，不冒称完整设计 |
| 新设计或局部改稿 | 人物理解→意图→相关专项真实设计→整合复核 | 当前范围完整可画推荐及修改结果 |
| 成熟稿要提示词 | 标provided/captured，核结构后编译 | 完整可复制正文，默认后台JSON/TXT＋唯一人用文档 |
| 只有浅定位却要提示词 | 原委托内补当前具体结构 | 设计完成再出词，不问是否调用已有能力，也不让用户逐参数选择 |
| 正式生产／打包 | 真实工程当前阶段与依赖 | 真实记录、图片、审查和批准；不能只给路由清单报成功 |

独立创作无需project.json、资产表、正式ID、全员规划。实际task的 `requested_dimensions` 可选 `face,hair,skin,body,costume,adornments`；只检查所需域。正式scope依然是identity/body/costume／旧complete，requested不是新增生产阶段。若实际给了 `project_root`，必须是真实工程，验证错误不能静默降级独立任务。

## 已批人物试改

先读当前正式父约束，普通局部变化写本轮artifact/draft并核保持项。未确认采用前不submit覆盖active批准、不让旧图提前失效；冻结delivery可在ledger外产候选词。采用后按现有submit/approve登记并复核受影响头像、表情、全身和执行图；复用理解不等于旧图代表新发型。实际冻结命令见[专项交付](specialist-contract.md)。

## 交付与成功

人默认只用一份持续角色设计文档：完整设计、修改结果、当前完整提示词；图片另存。JSON/TXT、来源、版本、验证和会诊记录放内部。提示词默认文件双份同源；本次用户明确只要对话时 `delivery_mode:text` 才免文件。不能把设计／prompt请求事后降为discussion以过门。

文本成功须实际完整正文或可解析的真实正文引用，不只有summary；文件成功须存在且对应本次成果。结构通过不等于理解、美感或审图通过。任务缺口尽量自行补，真正冲突、重大剧情身份变更及已有批准规则要求的事项才集中交用户决定。

正式 `plan` 给当前可做frontier：缺context就读／复用，缺设计就做，已有稿先核，不把缺记录名自动变用户材料清单。资产模式individual用常规四图；speaking_extra、ensemble按[群演合同](group-ensemble.md)各状态单图，非人按给定形态；不替人造器官或阶段。

正式图序、阶段依据与兼容见[工作流](workflow.md)、[分阶段](phased-design.md)；具体方法见[人物总控](director-understanding.md)与[专项合同](specialist-contract.md)。
