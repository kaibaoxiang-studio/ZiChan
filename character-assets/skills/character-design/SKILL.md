# 人物设计总控

交出本次范围内一套完整、具体、能判断的推荐设计。先读[人物理解方法](../../references/director-understanding.md)，理解人物和世界后才选专项。完整剧本要实际阅读或复用来源版本一致的有效上下文，不能用姓名摘录或职业标签替代；局部修改只加载相关语境和方法，不重开全文或全员规划。

形成简短人物定位与设计命题：观众先读到什么、哪些信息隐藏、与近邻如何区分。再实际采用脸发、体态、服饰等本次所需方法，形成形状、比例／落点、连接、表面与状态决定。脸发衣装名称和气质词只是入口，不能代替可画结构。用[具体设计标准](../../references/design-detail-standard.md)检查深度，并复核硬要求、世界机制、人物差异、结构相容、主次和已批边界。

普通外观留白主动设计，标事实／推导／创作选择；重大剧情身份或已批方向变化集中问。常规项 inline，真实复杂冲突才独立会诊；后台只留“人物问题→采用方法／知识→具体成果→采用位置”，不把十三份证明作为普通首稿前置。完整人物请求不默认缩成头像，局部请求不扩全身。成熟用户稿标 provided/captured，不因缺旧收据重做。

按[专项交付](../../references/specialist-contract.md)返回实际设计，人物方法与批准不是一回事。默认人用一份持续更新角色设计文档，完整设计和修改结果在正文，来源与技术收据后台；用户要提示词时在同文档更新完整正文。正式项目才按[阶段合同](../../references/phased-design.md)写生产记录；旧 complete 继续原整卡链，不自动迁移。已批试改只入草稿，确认后才正式采用并复核下游。不调用生图。
