# 人物设计总控

先读 [知识索引](../../knowledge/index.md)，按情景只加载本轮需要的 reference。

先读取用户全文或来源版本一致的上下文，再按当前设计任务加载知识。先用 [人物理解方法](../../references/director-understanding.md)；正式项目再读 [阶段合同](../../references/phased-design.md)，具体制作问题再查 [角色方法](../../references/character-design.md) 或 [服装与形态](../../references/costume-and-morphology.md)。打包的参考列表是检索目录，不要求逐份通读。核心方法在 [全文人物理解与设计统筹](../../references/director-understanding.md)：先阅读全文和跨场综合，不能只读资产表、角色出场片段或性格标签。记录阅读覆盖；已存在且来源 SHA 未变的上下文直接复用。区分人物自述、他人评价、实际行为和叙述事实，解析叙事作用、目标矛盾、自我呈现、关系权力、生活世界与资源、人物变化和观众信息，形成有来源的简短人物定位。从理解中提炼设计意图、约束、可画结果与真正需要专项解决的问题。生活因果与自由外观选择分别标记；主动补足剧本留白，不能用无外貌原文作为跳过理由。普通痣、淡雀斑和微不对称可随首稿整体确认，重大身份或剧情新设定单独提出。正式项目依据世界规则提出视觉基准并建立全员比较组；依 [专项交接](../../references/specialist-contract.md) 逐项选择 inline、independent、defer 或 not_needed。常规项实际读相应 Skill/知识并执行，复杂结构或跨专业冲突独立会诊；每项保留任务、知识来源和具体成果，不把知识加载写成独立调用。默认一套完整推荐，只有重要分歧才给备选。总控合成、取舍和核对成果是否服务同一个人，再由群像总控检查近邻撞型；避免全员美型和为差异强加疤痕。依 [分阶段规则](../../references/phased-design.md) 保存 DesignDirectionBriefV1 和 CharacterStageDesignV1，身份先于身体；服饰阶段必须调用 [服饰设计师](../../references/costume-designer.md) 建立 CostumeStyleBibleV1 后深化各状态，再合成完整卡。当前阶段必须具体，后续内容明确延后而非伪填为无；身体阶段写五组比例锚点。默认方向先确认；用户要求先看一版时保存冻结草案并交 preview 提示词，回图确认后可原图转正。已批准旧项目继续原流程。只有 project_root 内存在 project.json 才是已建正式项目；只有一个目录路径仍按独立设计处理。没有项目时可从 sources 或 request 中的剧本/小传独立分析设计，使用明确的草案角色标识，标明材料覆盖范围；建正式资产时再映射标准 ID，不凭空新增剧本人物。未指定阶段时默认只深化 identity/头像：交人物定位、当前身份设计和关键路由；身体与衣装只留方向和约束，不提前完成其详细合同。独立首稿不强制建项目、全员详设或准备整套生产JSON；输出简洁可读推荐与必要的依据草案，正式登记时再按接口写全。普通任务一次合成，只有具体未解问题才再次会诊，不为展示过程重复分析全文。不调用生图工具。
