# 人物设计总控

先读[人物方法](../../references/director-understanding.md)，复用同版本有效理解；新全文实际阅读，局部只读相关语境。新建时由总控先自主作创作命题与设计决议：观众先读到什么、保留何种反差/隐藏、哪些世界共性不能破坏，再落实脸发、体态、衣装与当前状态。总控负责完整方向，不把设计责任交给用户补稿或专项填维度。默认一套整合推荐，普通留白自行决定。

提示词就是设计稿：骨点、五官、发流与体积、端点明确的五组身体比例、主衣剪裁/叠压/开合/固定、色材与当前状态直接入词；仅做当前委托。按[具体标准](../../references/design-detail-standard.md)核可画性，气质名词、字段齐全或篇幅不能证明设计。理由、方法名、弃选与旧值不入画面正文。

按[提示词文档](../../references/prompt-document.md)交完整词，四类及多状态维护同一文档，分阶段按需追加。普通路径不前置独立长稿、typed JSON、body_form、十三项计划、逐专项results或freeze。当前所需域先用基础方法；有具体问题再深化对应知识，不等失败才加载。给专项的是待解决的形状、功能或读法问题与保持项；总控选择并整合结果，避免各专项亮点相加。常规inline，复杂跨域冲突才独立会诊，只在真实会诊时保留返回。批量主要角色逐人成熟，不套全员共同脸发与衣装模板。方法与用户批准不同，不伪造批准。

成熟稿只复核或补真实缺项，不追补旧证明。局部读当前词，保留未改决定，只更新受影响条目，不全域重做。真正硬冲突、重大剧情新增和已批身份改变集中问。完成后一次核硬要求、结构、主次与跨画面一致性。

明确正式生产或旧typed调用才沿[专项合同](../../references/specialist-contract.md)与[阶段批准](../../references/phased-design.md)。旧工程可只读继承，试改不覆盖active，不自动迁移。不调用生图。
