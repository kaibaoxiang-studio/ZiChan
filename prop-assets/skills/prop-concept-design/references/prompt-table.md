# 批量道具 Prompt 表

用于“剧本／资产道具表 → 道具 Prompt 表”的整表交付。输出是包含视觉设计的完整出图词，不是只把道具名称和原描述搬到新表。

## 1. 三种输入都能开始

| 输入 | 如何确定范围 | 来源边界 |
|---|---|---|
| 剧本＋资产表 | 默认以表内道具为范围，对照剧本补用途、动作与明确外观 | 保留原ID；表外发现单列候补；冲突不自动裁决 |
| 只有道具资产表 | 按指定道具工作表、栏目或条目生成 | 保留原ID；剧情未提供就不编造集场、动作或经历 |
| 只有剧本 | 在用户指定文本范围提取画面中实际需要的道具，建立工作清单 | 无原ID时用明确标注的工作编号；纯台词提及与身份疑点分开，不冒充正式资产清单 |

读取真实文件结构，不要求用户先转换固定格式。记录已处理范围；未读完的剧本不能声称覆盖整剧。只有表时不强求补剧本，只有剧本时不强求补表；未提供道具图不构成阻碍。

已有图片、用户明确要求与选定方案可直接作为约束。统一视觉风格优先采用用户描述或参考；若未知且不阻碍提案，选一个与已知世界观相容的暂定表达并在表前说明，不把它当成已确认全剧风格。

## 2. 直接把必要设计写进整表

1. 确定工作清单，保留原ID、名称、状态及父子关系；重复出现不重复造新资产，同名或别名身份不清时列疑点，不静默合并。
2. 从已有来源提炼用途、交互与明确外观。把材料、颜色、结构等未写明内容作为设计补全，不把补全伪装成剧本事实。
3. 给每件道具形成满足约束的推荐设计，补足轮廓、关键结构、相对尺度、材质、固有色与必要纹样。无需每件都先交多个方向等待选择；用户要求逐件确认时才按该节奏执行。
4. 在同一项目风格下，按下文固定结构写逐行完整提示词。普通道具可简洁，关键道具可深化，不强制每件豪华装饰、做旧、发光或全部专项齐备。
5. 检查清单覆盖、身份与状态关系、明确约束、设计互相兼容和提示词可复制性，再交付表格。

要求整表意味着可以把未确认设计提案写成具体出图词，不意味着提案已经定稿。关键身份、功能或明确外观冲突只阻碍相关条目：保留该行、注明原因，必要时暂空其完整Prompt，不用相互矛盾的词凑齐全表；其他条目继续。

## 3. 表格约定

默认字段如下，可适配团队已有模板，不要求用户补填这些列：

| 字段 | 内容 |
|---|---|
| 道具ID／工作编号 | 保留原ID；自行工作编号明确标注，不改号 |
| 道具名称 | 沿用来源名，有别名另注 |
| 状态／图类型 | 常态三视图＋一个局部细节特写（同一张资产图），或用户另行指定的图类型；与同一基础道具关联 |
| 剧情用途／使用者 | 仅写来源支持的信息，未知写未提供 |
| 设计说明 | 简述轮廓、结构、材质、配色与必要纹样；分开写明确要求和本次设计补全 |
| 完整Prompt | 每行一段可直接复制的完整出图词，包含共同风格与该行关键限制 |
| 保持／排除项 | 便于审核的摘要；执行所需关键限制同时写入完整Prompt |
| 来源／疑点 | 可定位的表行或集场，关键冲突与未定假设；不编造页码 |
| 交付状态 | 如“Prompt已完成·设计未确认”“已有方向·待出图”“待澄清”；不写已生图或资产定稿 |

默认每个基础道具对应一行常态三视图资产图Prompt，正面、侧面、背面与一个局部特写合在同一图中，不另造四个资产或状态ID。上游明确列出的状态也应有可追踪行；基础造型未锁图时，可写继承同一文字方案的状态草案，并标注“待主视觉锁定后核对”，不能冒充图像一致性已验证。用户只要常态表时，其他状态列为未纳入本次范围。

一行只表达一个图目标；同一常态的三个观察方向与特写属于同一目标，不把常态、破损、启动、开合混在不同视图中。除用户指定的三视图＋特写，不增加角色持握、新状态、更多视角或模型参数。

完整Prompt按目标描述道具身份、可见造型与结构、相对尺度、材质和固有色、必要纹样与表面特征、统一风格和展示条件。默认中文，不强制双语；不得只写“同上”“按该行设计说明”“参考所有图片”。有图时点明实际参考及用途，无图时不假定必须上传一张不存在的道具图。

### 固定结构提示词

道具资产图的每行Prompt先使用以下固定正文，仅替换道具名称：

```text
生成一个实体道具三视图资产图，白色或浅灰色背景，展示【道具名称】的正面、侧面、背面，并增加一个局部细节特写。道具整体造型、颜色、材质、比例和关键结构必须保持统一。
```

随后按以下顺序补全，并合成一个可直接复制的完整单元格；不让用户自行拼接固定前缀和设计字段：

```text
道具设计：【明确本件的轮廓、部件、相对比例、材质、固有色、纹样及本次状态。】
局部细节特写：【只指定一个部位，以及该部位需要看清的材质或结构。】
视觉风格：【沿用本项目的已确认风格；未知时使用明确标注的暂定提案。】
排版与一致性：同一张图内，上排从左到右为正面、侧面、背面，下排为一个局部细节特写；三视图采用相同主体尺度，特写只放大对应部位，不改变设计。各视图完整、分区清晰、不互相遮挡，柔和均匀照明，无人物、手、场景或水印。【补充该道具的必要排除项。】
```

- “实体道具”指剧情中的具体物件，包括有来源的幻想材质或微光道具；不要求改成写实金属、可制造物件或取消已知魔法表现。
- 三视图为资产展示规范，不自动承诺精确工程正交、制造尺寸或三维结构验证。背面与内部未由来源给出时，补全仍是未确认提案。
- 柔性道具（鞭、链等）在三视图中保持同一摆放形态和部件数量，改变观察方向，不重新盘绕；薄片文件保持页数、叠放关系，侧面展示纸层厚度，背面不新增无依据正文。
- 项目内沿用同一背景、排版和风格。固定的是展示结构，具体造型与特写部位按道具填写；不强制所有道具共用一种材质、颜色、纹样或效果。
- 用户单独要求一张单体主视觉、某个状态或修图时，目标覆盖本默认模板；不强行加三视图。模板中的“生成”是交给外部出图工具的指令，交付Prompt不等于授权自动生图。

## 4. 交付与结束

默认在回复中给可读表；用户指定文件格式时导出新文件。长表可分批写入同一输出表，并报告总清单、本次完成、待澄清与尚未处理条目；用户授权整表时，不因每批结束再次索要相同授权。

交付前逐条对账：范围内每件道具是已写词、待澄清还是未纳入；检查遗漏、重复、状态混写和原ID不对应的问题。道具资产图的完整Prompt必须包含固定正文、三个方向、一个明确特写部位和同图一致性要求。不要用“已完成”掩盖未处理条目。

交付表格后即完成本轮提示词任务；可说明后续由团队出图回流，但不强制先提供单件图片，不自动生图、锁定设计或启动所有派生任务。
