# 知识来源、证据与待补项

在核对知识来源、要求历史考据或继续补库时阅读。普通设计只需在使用相关知识时记录最小依据，不必每轮重读来源表。

本次接入将用户两份压缩包中的 32 篇 Markdown 整理为两个专项。保留来源标识和使用边界，不复制全部原文，不改动原压缩包。下列映射表示内容整理关系，不表示已核实其中的史实或作品设定。

## 1. 依据类型与核验状态

| 依据类型 | 可支持什么 | 不能推定什么 |
|---|---|---|
| 史实资料 | 有明确出处的年代、形制、材质、用途等具体判断 | 单一例子代表整个时代/地区；未核实摘要等于考据结论 |
| 作品设定 | 指定作品和版本中的道具、角色或能力 | 虚构内容是真实历史；改编版本与原典完全一致 |
| 设计启发 | 轮廓、配色、材质、状态等候选表达 | 属于剧本事实或所有同类的硬标准 |
| 待核实 | 提纲、二手概括或来源不明的具体说法，暂存以便查证 | 可以因被反复引用或用户选图而自动成为已核实 |

核验状态独立记为“未核实 / 已核实 / 有争议 / 不适用”；设计启发的审美取舍通常不适用史实核验。只有实际检查了支持该具体说法的资料，才记已核实，并记录支持范围。出处不完整、版本混用或资料冲突时保留限制。

项目约束另记“剧本明确、资产表设定、用户要求、设计推导、待确认”。例如用户确认自创符文，可以成为项目要求，但它仍不是已核实的历史符文。

建议最小记录：资料名称/具体章节或对象；依据类型；核验状态；借鉴点；适用范围与改动。涉及史实、真实符号或作品复原时，再补年代/地域或作品版本、出版物页/图号或馆藏编号、可定位出处和实际查证结果。不能编造引用、馆藏编号或测量值。

## 3. 待核实项的处理

- 两份原库未提供文献、馆藏、原物图或作品版本定位；本次未完成逐条外部核验，不输出“已考据”的结论。
- 神话库混合神话、文学、游戏与影视案例。需要具体作品/神话复原时，先确认来源及版本，再查证属性、归属与叙事，不从“经典案例”列表直接推导。
- 装备史库的时代演变、译名/品类、地域概括、佩用习惯和案例归类均需按具体对象核验。本次移除其作为通用硬规则的作用，不在无证据时反向写另一套历史答案。
- 原资料中的固定数量、颜色、大小、体型、磨损和装饰要求降为设计候选。审核以已确认项目要求为准，不把“参考中建议”写成强制返工理由。
- 有争议时记录具体说法、出处与对本件的影响。仅针对当前需要的点核验，不自动扩大为全库检索、实际剧本试跑或批量生图。

## 4. 后续补库的优先项

按当前项目是否需要决定先后，不要求先填满知识库再设计。

| 缺口 | 最小有用资料 | 当前能做与不能声称的事 |
|---|---|---|
| 可靠原物与文化视觉依据 | 可定位的原物图/出版物、名称、年代/地域、出处、可借鉴部位；实际尺寸需有测量来源 | 可以做标注假设的历史启发方案；不能称为严格复原或凭图片给精确尺寸 |
| 神话/作品来源体系 | 典籍篇章或明确作品版本，能力、归属与限制的可核对证据 | 可以使用已确认项目设定；不能把混合影视案例当作原典 |
| 魔法机制与状态示例 | 已确认的触发、作用、限制/代价、状态转移与前后视觉参考 | 已补记录方法；未补实证案例，不编造能力或要求完整状态循环 |
| 非武器专项深度 | 信件/契约、印章/令牌、仪式器具、药物/内容物、软质物件的结构、尺度、交互与实例 | 保留原流程入口，按功能提出补全；本次没有声称已建立这些专项知识库 |

接收新资料时，先判断它支持哪个当前设计决定，记录证据和借鉴边界，再接到相关专项。与现有通用方法重复的内容只补有效例子，不增加重复规范或空目录。
