# 输出与进度约定

使用最小必要字段。默认可读 Markdown；只有用户或下游需要时使用 JSON/YAML 或工作簿，不强迫用户先补固定格式。这里的模板是字段约定，不要求每轮交付所有模板。

## 主交付：道具 Prompt 表

用户要求从剧本或道具资产表交付Prompt表时，采用 [批量 Prompt 表](prompt-table.md) 的字段与覆盖规则，并使用其中的固定三视图提示词：每件一行，目标为同图正面、侧面、背面＋一个局部细节特写。需求、设计补全和完整提示词汇入一张表，不把下面各阶段模板变成团队必须逐件填写、确认的前置作业。提示词完成、设计确认和图像定稿分别记录。

## 1. 项目约束卡（P0）

- 输入与覆盖范围：剧本/清单的版本、处理范围。
- 目标：视觉风格、世界观、下游用途。
- 参考：知识目录、已有图片，各自负责什么。
- 协作：本轮范围、出图方式和当前缺口。

未知项填“待确认”或明确假设；不填看似真实的默认设定。

涉及时代文化时，可补充考据模式、时代/地域、适用阶层与装备体系，字段见 [时代文化与装备体系专项](era-and-culture-equipment.md)。不要求无关项目填写。

## 2. 道具准备清单与需求卡（P1）

清单建议列：原 ID / 名称、来源位置、剧情用途、当前节点、关键疑点、建议设计深度。

单道具需求卡：

```text
资产：原 ID、名称、状态/子项关系
来源：表位置、实际集场/短摘录
叙事用途：为什么需要这件道具
使用者：归属、操作者、角色参考
明确约束：内容 + 来源等级
交互与状态：动作/状态 + 触发依据
设计补全：轮廓、部件、尺度、材质、配色、符号等缺口
拟交付：主视觉、必要视角/状态/示意及理由
待确认：只列影响当前推进的问题
```

有资产表时，表外候补、身份疑点与资料冲突单列；只有剧本时，提取清单标为工作清单，不混称已确认正式资产。

调用知识资料时，只为影响设计的判断记录“资料名称/章节、依据类型、核验状态、借鉴点、适用边界”，规则见 [知识来源、证据与待补项](knowledge-sources.md)。项目来源与知识依据不互相替代。涉及魔法、活体或变形时，按 [神话与魔法道具专项](myth-and-magic-props.md) 的“能力与状态补充”记录必要字段，不增加无依据设定。

## 3. 设计方向记录（P2）

每案包括概念、轮廓/关键结构、材质/配色、世界观特征、功能适配和取舍。结尾分别写推荐方向及理由、用户选择/授权和版本；未选择时不能记“已定稿”。批量Prompt表可将推荐提案直接写入设计说明及完整词，状态仍标未确认，不要求先另交方向记录。

## 4. 提示词包（P3/P5/修图）

```text
目标：资产 ID、基准/方向版本、本次图类型
参考图：具体附件或文件；逐张说明锁定造型/风格/角色/状态
完整提示词：可直接复制的正文
必须保持：身份不变量及本轮锁定内容
允许改变：目标视角、状态、姿态或局部修复区域
限制：与目标相关的排除项、已知工具限制
回流：需要用户返回的实际图片和本轮核查重点
```

修图包额外指出实际问题位置、期望修正及不动区域。只有新图回流并检查后才更新解决状态。

## 5. 审核单与主视觉基准卡（P4/P5）

审核单记录：图片位置/版本、对应要求、实际观察、问题等级、建议动作、助手审核结果、用户选择与接受的差异。

审核结果可用“需返工 / 可用于锁定 / 有限可用 / 信息不足”，不得以伪精确评分代替关键问题。

基准卡：

```text
资产 ID：
基准版本：
已确认图片：具体文件或附件，不用“上面那张”代替可定位来源
确认依据：用户明确选图记录
身份不变量：轮廓；部件数量/位置；比例；材质/固有色分区；识别符号
尺度关系：有来源的尺度或设计建议，二者区分
待补结构：未见背面/内部等
允许变化：已定义的视角、状态和交互变化
已知问题/接受差异：
```

涉及明确的变形设计时，另记形态对应关系、允许变化的结构和跨形态身份线索；新形态图片未回流前，只登记文字设计，不记为已确认图片。

## 6. 派生清单与交付索引（P5/P6）

派生项记录：工作编号、父资产/原状态 ID、基准版本、图类型、用途/依据、保持与改变、当前状态、文件、审核和用户选择。

没有正式状态 ID 时使用明确标注的工作编号，不伪造上游编号。计划项不填不存在的文件路径。

交付索引包括：

- 本次范围和基础资产清单。
- 已确认主视觉、视角、状态/交互图片及其版本关系。
- 设计说明、提示词、参考用途和必要文字内容。
- 未完成项、已知限制、接受差异和下游注意事项。

## 7. 最小进度记录

多轮或批量任务维护一个轻量进度文件，保存到用户约定的输出位置；短单轮任务可先用回复记录。不要求创建额外数据库或固定仓库。

```text
项目：输入版本、输出范围、当前风格/参考
每个资产：
  原 ID / 名称
  当前节点：P0—P6
  当前状态：进行中 / 待用户选择 / 待图片回流 / 需返工 / 本阶段完成 / 交付完成
  已选方向与版本
  当前基准图片与版本（未确认则为空）
  派生项及其基准版本、实际文件、审核/选择状态
  未解决项、已接受差异
  下一动作与最小输入
```

更新记录时保留用户确认和旧版本，不把“等待”记成“完成”。基准改版后，明确标出依赖旧版的派生项需要重核。
