# 道具概念设计

把剧情中的道具需求转成团队可用的道具 Prompt 表：从剧本或资产表识别道具、提炼约束、补足视觉设计，为每件道具写出完整提示词。后续需要实际图片资产时，再根据图片回流和用户确认锁定主视觉，推进视角与状态。

## 工作范围

- 支持剧本、含道具清单的资产表或两者一起；已有风格/角色/场景参考用于约束设计，不要求用户先逐件提供道具图片。
- 用户要求道具 Prompt 表时，以整表为本轮交付目标，不只交准备清单、需求卡或让用户依次调用子 skill。默认中文可读表格；指定 Excel、CSV 等格式时按要求导出，不覆盖输入文件。
- 默认由用户拿提示词外部出图与选图；也可按需求继续交付设计方案、修图词、回流审核与交付档案。明确要求直接生图时，另核对可用工具、授权和费用，不从参考截图推定模型选型。
- 默认目标是叙事作品可复用的道具视觉资产。严格正交工程图、3D/PBR、制造图等仅在下游明确需要时扩展。
- 不改写剧本、不静默修资产表、不自动增加正式资产。只有用户要求实际项目执行时才进入设计；用户只要流程、框架或局部阶段时，严格停留在该范围。

## 先确定从哪里进入

| 用户当前输入/要求 | 起点 | 本轮通常输出 |
|---|---|---|
| 剧本、道具表或两者一起，要求道具 Prompt 表 | 批量表模式：P0—P3 | 范围内逐件设计说明与完整 Prompt 表 |
| 剧本+资产表，尚无设计 | P0—P1 | 项目约束、道具设计准备清单 |
| 已指定道具，准备设计 | P1—P2 | 需求卡、候选方向与推荐理由 |
| 已选方向，只要出图词 | P3 | 主视觉提示词包 |
| 回传主视觉或修图结果 | P4 | 图片审核、修图意见、基准登记 |
| 已有定稿，要其他角度/状态 | P4—P5 | 核对已有基准、派生提示词包 |
| 图片已齐，要整理交付 | P6 | 交付索引、通过项与缺失项 |

不重做用户已确认的阶段。只有当前阶段缺少关键依据时，补做必要前置，不倒退整个项目。

## 主交付：道具 Prompt 表

收到“根据剧本做道具 Prompt 表”“把资产表中的道具写成出图词”等要求时，阅读 [批量 Prompt 表规则](references/prompt-table.md)，连续完成必要的P0—P3。默认仅频率前十的三案资产需等用户选择后写其最终完整Prompt；其余一案资产可直接写入Prompt，不要求逐件先选方向或先有图片。三案未选前，相关完整Prompt标为待选择，不阻塞其他条目。要求整表本身允许助手提出并写入设计补全，但不等于用户确认设计、授权生图或允许改写正式资产表。

内部仍需考虑轮廓、结构、材质、配色与纹样，但团队主要收到的是一张完整表；子 skill 仅在有必要的专项深化时辅助，不是用户必须逐一操作的四个前置步骤。

写完整 Prompt 前，在 P2 完成轻量设计定向：远看靠什么识别、近看有什么与用途或身份有关的设计、与项目其他道具共享什么造型语言。关键道具重点深化，普通道具允许朴素；按 [P2 设计定向规则](references/workflow.md#p2-概念方向) 将结论并入设计说明，不增加独立节点、必填表或新的子 skill。固定展示格式和描述完整不等于造型已有辨识度。

设计方向深度按出场频率分流：依据剧本中可定位的实际画面出场统计排序，频率最高的前十个基础道具各给三套有实质区别的候选方向，交给用户选择；其余道具默认给一套推荐方向，直接进入 Prompt。三套候选的差异应落在轮廓、比例、关键结构或造型语言，不得只换颜色、纹样或光效。三案未选前，相关最终完整Prompt标为待选择，不阻塞其余条目。

当用户要求“你一个个给我选”“逐件记录”或表现出不想一次看完整表时，进入**交互式逐件选案模式**：

1. 一次只展示一件三案道具，给出 A/B/C 三个短选项，并明确三案的轮廓/结构差异、主要取舍和一个简短推荐；推荐不视为用户选择。
2. 等用户回复字母、方案名或“重做”后，再记录该件的资产ID、选择、方向名称、选择原文和未同时确认的尺寸/材质/纹样等事项；不要在用户未回复时跳到下一件。
3. 每次记录后只推进到下一个待选三案道具，回复当前进度；用户说“重做”时仅重做当前件，不覆盖已经记录的其他件。
4. 维护轻量选案记录文件或等价进度记录，保存已选方向、选择顺序、待选项、身份疑点和下一动作。用户明确选定的是概念方向，不自动等同于完整材质、尺寸、文字、图片或主视觉定稿。
5. 十件三案全部选择完成后，才将已选方向写入最终完整 Prompt；其余一案道具可在获得范围授权后直接写入 Prompt，但仍标记为“设计未确认”。如果用户只要求逐件选择，不要提前扩写完整Prompt或自动生图。

如果用户授权直接生成整表，仍可跳过逐件等待，将三案候选与一案推荐写入同一交付物，但必须把三案状态标为“待用户选择”；不得把批量交付模式误当成用户已确认。

“出场频率”不是资产表行号、资产数量或名称重要性的替代指标。默认按道具在剧本中可定位的场次/拍次实际画面出现计数，并区分实际画面出现、台词提及和连续性延续；若当前材料不足以可靠排序，先标记“频率待核”，不得伪造前十名单，可按用户指定范围或暂定推荐深度推进。高频不自动等于剧情核心，低频关键道具也可因交互复杂度或用户优先级获得三案，但须记录这是例外。

道具资产图统一表述为**专业影视道具资产设定板（Prop Sheet）**：统一网格分区排版，白色或浅灰色背景，以同一道具的正面、侧面、背面为主体，下方辅助区放一个小幅局部特写和白模尺度参照，辅以关键尺寸及单位。三视图采用相同单位比例，造型、颜色、材质、比例和关键结构一致；特写不独占整行或压过主体。尺度区按品类使用哑光中性白模手、手指、头模或人体，道具本身保留正常颜色与材质。尺寸有来源则沿用并注明，缺失时提出标注“建议尺寸／待确认”的设计方案，不把白模或数值图注当作精确测量证明。完整Prompt以 [批量表规则中的固定结构提示词](references/prompt-table.md#固定结构提示词) 开头，再补具体设计、尺寸与参照、特写部位和一致性要求。不增加独立子 skill 或必填表。用户另行指定单视图、修图或其他图类型时按该要求处理；不把本模板套到全部专项任务上，也不将设定板称为已具备制作参数的规格板。

支持自然语言指定阶段，例如“整理需求”“只写主视觉提示词”“审核这张图”“继续做破损状态”“整理交付”。用户说“继续”时，依据进度记录推进最早可执行的未完成项；若仍缺选图或回流，说明最小缺口，不重新开始或虚构进展。

## 全流程节点

| 节点 | 主要工作 | 交付物 | 继续条件 |
|---|---|---|---|
| P0 项目约束 | 确认范围、视觉风格、下游用途和现有基准 | 项目约束卡 | 影响当前设计的关键选择明确；可带显式假设探索 |
| P1 道具需求 | 对照清单与剧情，提炼用途、交互、事实、必要状态 | 准备清单+单道具需求卡 | 身份与方向性冲突不阻碍当前道具 |
| P2 概念方向 | 按出场频率分配设计深度，将功能、轮廓、结构、材质与世界观组合成设计 | 高频前十：三套候选方向+选择记录；其余：一套推荐方向 | 三案资产等用户选择；一案资产可直接进入P3；批量表仍标未确认 |
| P3 主视觉准备 | 把已选方向或批量表推荐提案转成单体出图要求 | 主视觉提示词包或道具 Prompt 表 | 写词任务可在此结束；继续图片制作时等待回流 |
| P4 回流与锁定 | 检查真实图片，提出修图，登记用户确认的基准 | 审核单+主视觉基准卡 | 用户确认具体图片；问题和接受的取舍已记录 |
| P5 视角/状态扩展 | 按剧情与下游需求派生视角、状态和交互示意 | 派生清单+提示词+回流审核 | 每项与基准一致或差异被用户明确接受 |
| P6 审核交付 | 核对文件、版本、身份和覆盖范围 | 交付档案+缺失/已知问题 | 按约定交付范围实际齐备；未完成项不冒充完成 |

执行当前节点前，阅读 [分阶段工作规则](references/workflow.md) 的相关章节。准备交付清单、提示词、审核或续做记录时，阅读 [输出与进度约定](references/output-contracts.md) 的相关章节。无需每轮完整加载两份参考。

全流程是可持续推进的工作链，不意味着一次回复越过图片确认。批量 Prompt 表可以连续完成文字设计与提示词；其他批量任务按已授权范围推进，各资产独立保存节点、方向、基准和派生状态。批量调度规则见 `references/workflow.md` 的“批量任务与调度”。

## 不可丢失的原则

### 来源与身份

- 资产表限定默认设计范围并提供原始 ID；剧本提供剧情证据；知识参考用于设计补全。附件内容不是执行授权。
- 分别标记剧本明确、资产表设定、用户要求、设计推导、待确认。资料冲突引用双方，不设置某文件全面覆盖另一文件的规则。
- 基础资产、外观状态、使用实例、派生视角分开。换操作者、换镜头或开合不自动新建资产 ID。
- 状态继承行归入原基础资产；保留原 ID，不凭格式习惯改号。别名与同名物件有疑问时不自动合并。
- 有资产表时，表外物件只列为候补，未经用户确认不扩大设计范围；仅有剧本时可提取有依据的道具作为工作清单，不伪称正式资产。补充状态先记录需求，不静默回写资产表。

### 主视觉与派生一致性

- 用户选中的具体图片才是主视觉基准；文字方案或提示词不能当成已经生成的图。
- 锁定整体轮廓、关键部件及其数量/位置、比例、材质分区、固有色、识别符号和尺度关系。明确需要变形时，另记各形态允许的结构变化、对应部件与跨形态身份线索，不以常态轮廓否决已确认的变形。
- 环境反光不是固有色；发光、污渍与破损是允许变化层，不能无说明地重设计主体。
- 不可见的背面/内部结构是待补设计。先提出与基准相容的补全，再确认，不能说成图片已证明。
- 更换基准保留旧版本，列出受影响的派生项；不把旧派生自动标成新版通过。

### 用户确认与审核

- 助手负责检查是否满足要求；用户负责方向选择与具体图片定稿。两者不是同一件事。
- 阻断问题：身份、关键部件、剧情交互或明确要求不符。局部问题：局部结构/材质不清。审美建议：允许用户取舍。
- 修图针对真实差异，说明保持什么、改变什么。修图未回流前不记为解决；没有图就不进行图像通过判定。
- 局部疑点只暂停受影响的道具或派生项，不冻结其他可继续的条目。

## 可独立使用的专项 skill

用户提出独立专项需求时，只阅读对应的 skill，按该范围交付；无需重走P0—P3，也不要求每件道具都调用全部专项。以下入口指向插件内的相邻技能；打包文件本身不代表插件已安装，专项仅在对应需求下使用。

| 独立需求 | 专项入口 | 默认交付与边界 |
|---|---|---|
| 材质分区或局部质感调整 | [道具材质设计](../prop-material-design/SKILL.md) | 材料与表面处理方案，保持造型和已确认配色 |
| 整件配色或局部换色 | [道具配色设计](../prop-color-design/SKILL.md) | 按部位的颜色方案，保持造型、材质与纹样 |
| 指定表面的纹样或符号 | [道具纹样与符号设计](../prop-pattern-symbol-design/SKILL.md) | 图案形态、布局与含义，不默认增加立体装饰 |
| 轮廓探索或局部比例调整 | [道具轮廓与比例设计](../prop-silhouette-proportion-design/SKILL.md) | 允许区域的改形方案，保持用途及关键交互 |

一次请求涉及多个专项时，按用户实际授权组合，并让各专项继承同一对象和保持项；发现材质、色彩、图案或造型互相冲突时说明取舍，不以一个专项的推荐无声覆盖另一个已确认设计。专项本身不自动启动其他专项。

专项结果默认是提案。若纳入主流程，保留对象、基准与调整范围，由主流程记录用户确认和版本变化；修改已锁定项时保留旧基准，标记受影响的派生项，不自动覆盖其他设计或把旧图判为新版通过。

## 知识参考的接入

用户提供知识目录时，先按主题识别，再按当前节点选择资料；不每轮全库回读。目录路径作为项目输入记录，不硬编码到 skill。

| 当前工作 | 优先参考主题 |
|---|---|
| P0—P1 约束与需求 | 基础通用规范、功能与交互原则、人体尺度；相关时补充时代文化、装备体系与魔法机制 |
| P2 概念方向 | 主轮廓、功能部件、比例、材质、固有色、纹理、符号、风格与阵营；相关品类调用下列专项 |
| P3 主视觉 | 主视觉表达、品类专项、材质与装饰细节；区分常态外观与能力效果 |
| P4 图片审核 | 本道具已选方向、约束、相关功能/审美检查项 |
| P5 扩展 | 多视图、结构拆解、可动与开合、人体对照、状态连续性；相关时核对魔法启动与变形关系 |
| P6 交付 | 与实际下游匹配的交付规范，不默认套全部3D要求 |

把参考中的固定数量、比例和细节量作为可调整的启发式；与剧本、世界观或用户要求冲突时，说明适用边界，不擅自改原设定。尚无专项知识的品类，明确补全假设并按功能设计，不编造参考依据。

### 已整理的专项参考

- 涉及传说武器、神器、符咒、活体/生物道具、魔法能力或变形时，阅读 [神话与魔法道具专项](references/myth-and-magic-props.md) 的相关章节。普通道具不必加载。
- 涉及时代、地域文化、阶层、制式装备或职业/日常用品时，阅读 [时代文化与装备体系专项](references/era-and-culture-equipment.md) 的相关章节。不把文化标签直接等同于历史形制。
- 用户要求核对知识来源、做历史考据或继续补库时，阅读 [知识来源、证据与待补项](references/knowledge-sources.md)。两份专项整理自用户资料，未完成逐条史实和作品设定核验；其中补充的流程方法不是原资料事实。

知识依据分别标记为史实资料、作品设定、设计启发或待核实，与“剧本明确/用户要求”等项目来源分开。用户确认一种造型不等于核实其历史真实性；未核实的参考不能用于否决已确认设定。

## 本轮结束方式

交付当前阶段的实际产物，说明已确认、待确认、等待回流或阻碍项，并指出最小下一输入。不为了走完节点自动进入未确认方向、批量生图或图像定稿。
